# 首启环境向导 + 入口门禁 + 版本更新（阶段二交互规格）

这份文档把 [`docs/env-wizard.md`](env-wizard.md)（阶段二**唯一需求来源**）翻译成**具体的界面行为**：用户从「双击应用」到「进入主界面」的每一步看到什么、能点什么、不能点什么、等待与失败时屏幕上是什么、键盘怎么走完全程。

面向的对象是**实现者**（渲染层 / 视觉 / 契约与编排）与**审查者**。它**不是**需求文档（"为什么要做"以 `env-wizard.md` 为准，两者冲突时以需求文档为准），也**不是**视觉规格（配色 / 间距 / 圆角 / 阴影 / 动效由视觉规格定）。它只说**交互**，而且说到可以直接照着做：**下面出现的每一句「文案」都是可以原样给用户看的最终措辞**，实现时不要再改写成别的话。

### 0.2 平台

阶段二的门禁与 Node 自动安装**只在 Windows 上生效**（需求文档第 14 节的明确不做事）。所以：

- Windows：本文全部适用。
- macOS / Linux：**不出现门禁层**（不提供一个点下去必然失败的门），也不出现「安装 Node.js」这一步；环境自检页照旧显示阶段一的只读结论与既有两个一键动作，另给「打开官方下载页」。
- 也就是说：**门禁三态、逐步引导、Node 安装通道、更新 Node 入口都是 Windows 专属界面**；「更新 pnpm」「重新打开环境向导」「环境自检页本身」在三个平台上都在。

### 0.3 键盘约定（全篇复用，第 11 节展开）

| 键            | 作用（在没有更具体规则时）                                             |
| ------------- | ---------------------------------------------------------------------- |
| `Tab`         | 在这个区域内的可聚焦元素之间按**阅读顺序**前进（不是按视觉位置）       |
| `Shift+Tab`   | 反向                                                                   |
| `Enter`       | 触发**当前焦点所在的按钮**；输入框里 `Enter` 等同「开始」              |
| `Space`       | 等同 `Enter`（原生按钮行为，不要拦）                                   |
| `Esc`         | **不改变任何东西**：收起展开区 / 退出全屏 / 在其他界面里退回（见 0.4） |
| `Ctrl+数字键` | 切页（1~9）。**门禁层显示期间一律不生效**（第 2.5 节）                 |

### 0.4 一条贯穿全篇的安全规则：`Esc` 只退、不前进

**`Esc` 永远不做「会改动这台电脑」的事**，也永远不等于「跳过门禁」。它的全部含义只有下面这一张表，界面里**不再给它任何别的解释**（照抄启动锁的既有形状：锁上时 `Esc` = 「不等了，先进入界面」）：

| 当时屏幕上是什么                         | `Esc` 做什么                                                               | 绝对不做什么                                 |
| ---------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| 启动锁（沿用既有行为）                   | 等于「不等了，先进入界面」                                                 | —                                            |
| 应用内全屏（沿用既有行为）               | 退出全屏                                                                   | —                                            |
| 门禁：挡住页 / 检查中 / 放行页           | **等于逃生口**：收起门禁层、进入主界面（不改任何东西、不写盘、不改变判定） | 不触发安装、不跳过步骤、不代替用户点「开始」 |
| 门禁：确认区展开着                       | 收起确认区（= 「取消」），并把焦点还给触发它的那个按钮                     | 不开始安装                                   |
| 门禁：下载 / 校验进行中                  | 等于当时那个按钮（「取消下载」）：停止下载、删掉临时文件，系统零改动       | **决不**停止安装、不动已经在跑的安装器       |
| 门禁：**安装阶段**（管理员权限询问之后） | **不做任何事**                                                             | 不停安装、不停止等待、不给"失败"的结论       |
| 门禁：结果区 / "不再等待"之后            | **不做任何事**                                                             | 不收起门禁层、不改写结论                     |

**键盘用户永远有一条不需要鼠标的完整路径**（逐节写明）；`Esc` 只是那条路径之外的"退路"，不是它的一部分。

## 1. 从「打开应用」到「进入主界面」：全景路径

```
双击应用
  │
  ├─ 先显示「正在检查」（不空白、不白屏），只读地看一眼这台电脑
  │
  └─ 检查结果
       │
       ├─ 缺东西（有证据）→ 【挡住页】三次 install，一次一步
       │      │
       │      ├─ ① 安装 Node.js（二选一：直接装 / 用版本管理器装）
       │      ├─ ② 安装 pnpm（一键装，可以「先跳过这一步」）
       │      └─ ③ 安装 dsh（一键装，不可跳过）
       │             │
       │             ▼
       │      三步完成 → 【放行页】「进入 DSH Console」（**不自动跳走**）
       │
       ├─ 够用 / 没测全 → 不挡：直接进主界面（没测全时多一条常驻黄条）
       │
       └─ 任何时刻都能点底部逃生口 → 主界面 + 常驻横幅（随时可回到向导）
```

**顺序上的硬要求（需求文档 5.2）**：`blocked` 时**不自动拉起 dsh、不自动打开 Harness、不进全屏**。用户从逃生口离开 `blocked` 时才触发一次自动启动（若设置里开着自动启动且本轮没试过）。

## 2. 门禁层：界面语义

### 2.1 挡住的是什么

| 项               | 结论                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 被挡住的范围     | **主内容区**：左栏 + 九个页面 + 状态栏。与启动锁盖住的区域**完全一致**（`styles.css` 的 `.boot-lock` 是 `inset: 0`，门禁层同款） |
| 不被挡的         | 顶栏（窗口能拖、能关），以及系统自己画的最小化 / 最大化 / 关闭按钮 —— 与启动锁同一条既有结论                                     |
| 为什么连左栏也挡 | 做成页面就能用 `Ctrl+2` 切走，硬门禁就没有意义了。所以它是**覆盖层**，不是左栏第 10 个页面                                       |
| 与启动锁的关系   | **互斥**：门禁层显示期间不显示启动锁。`blocked` 这一路根本不走自动启动，所以启动锁也不会出现；从逃生口进入主界面之后才轮到启动锁 |
| 顶栏层级         | 顶栏**不许**为了盖住门禁层而设 `z-index`（既有约定：启动锁要能盖住顶栏，门禁层同款）                                             |
| 单个门禁层       | 界面上**同时只有一个**门禁层容器，状态变化是同一个容器的内容替换，不是叠出第二层                                                 |

### 2.2 单向状态机

门禁层照启动锁的形状做成**只能单向推进**的状态机（需求文档 5.5，AGENTS 7.9 踩过的教训）：

```
idle → checking → (blocked | released | unknown) → escaped|entered → done
```

`done` 之后**界面不再被门禁切换**：探测照旧重跑、黄条照旧更新，但门禁层不会重新扣上来（既有的启动锁有两条自检盯着这件事，门禁层照抄）。

| 状态       | 屏幕上是什么                                                                                                 | 什么时候进入                           |
| ---------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| `checking` | 检查中卡片（2.3）                                                                                            | 渲染层挂载后立刻，直到第一份报告回来   |
| `blocked`  | 挡住页（2.4）                                                                                                | 报告显示：有步骤明确缺东西             |
| `unknown`  | **不显示门禁层**，主界面 + 常驻黄条（2.6）                                                                   | 报告显示：没有明确缺失，但有测不出来的 |
| `released` | 本轮挡过人 → **原地变成放行页**（2.11）；从没挡过人（健康机器首轮、或本轮是用户显式重开的）→ 见 2.11 第 9 条 | 报告显示：环境够用                     |
| `escaped`  | 不显示门禁层；主界面 + 常驻横幅（2.7）                                                                       | 用户在挡住页点了逃生口                 |
| `entered`  | 不显示门禁层；走正常启动流程                                                                                 | 用户在放行页点了「进入 DSH Console」   |

**"本次运行已经放行过" 的判定（界面行为）**：一旦走到 `released` / `escaped` / `entered` / `done`，本次运行**不再显示门禁层**，即使后来报告又变成缺东西。用户想再看到向导，只能用 2.8 的两条明路（横幅 / 自检页按钮）。

**下次启动**：门禁**重新判定**（"跳过"是持久化的、"逃生"不是）。判断依据永远是**当次探测的事实**，不是"上次向导走完过没有"。

### 2.3 `checking`：检查中

进入条件：渲染层挂载完成，第一份报告**还没有**回来。

元素与文案（从上到下）：

1. 进度指示（转圈，沿用启动锁那颗缺口环的形状）；
2. 主标题：**正在检查这台电脑上的运行环境**
3. 副标题：**大约几秒钟，不会改动任何东西**
4. 按钮行：
   - 主操作（**默认焦点**）：「先进入界面（环境还没准备好，我稍后自己处理）」—— 这是**逃生口**，见 2.7；
   - 次操作：「重新检测」（探测卡住 / 出错后想再试一次时用；第一轮进行中**禁用**）。

三条硬要求：

- **不许空白**：哪怕报告要等几秒，这一段文字必须先画出来（需求文档第 12 节第 12 条）。
- **逃生口在检查中也能点**（"我们的探测卡住"不能等于"用户被关住"）。
- 检查中**不显示**步骤清单（那时还没有结论，画一排灰步骤会让用户以为已经判完了）。

离开条件：第一份报告回来了 → 按 2.2 的判定进入 `blocked` / `unknown` / `released`。

### 2.4 `blocked`：挡住页

进入条件：报告显示至少有一个步骤是「缺东西」（需求文档 4.3）。

从上到下的元素：

| #   | 元素         | 内容与行为                                                                                                                      |
| --- | ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 标题         | **运行环境还没准备好**                                                                                                          |
| 2   | 副标题       | **下面几步装好之后，就可以进入 DSH Console 了**                                                                                 |
| 3   | 步骤条       | 三步的横向总览，每步带状态（已完成 / 进行中 / 待办 / 已跳过 / 没测出来）：**① 安装 Node.js** → **② 安装 pnpm** → **③ 安装 dsh** |
| 4   | 当前步骤     | 展开的卡片，就是第 3~6 节那一套「进入条件 → 元素 → 主次操作 → 等待/失败态 → 离开条件」                                          |
| 5   | 后续步骤     | 只显示标题与一句「等上一步完成」，**不可展开**（不要让用户点开一个点不动的卡片）                                                |
| 6   | 提醒行       | **另外还有 N 项提醒（可稍后处理）** + 「去环境自检看详情」。N > 0 时才出现；`warn` 类项**不是**缺失，不挡人（需求文档 4.2）     |
| 7   | 「重新检测」 | 次操作。任何时候都能点（安装动作正在跑时禁用，2.9）                                                                             |
| 8   | 逃生口       | 底部常驻，**永远可点**（2.7）                                                                                                   |

**当前步骤是哪个**（纯规则，界面只读结论，不自己判断）：「三步里的第一个不是『已完成』也不是『已跳过』的步骤」。如果第一步已完成、第二步待办，当前步骤就是第二步。

**挡住页上没有任何"直接进入主界面"的主按钮**：唯一的「前进」是逃生口，且它写明了这是一次放弃门禁的选择。

**挡住页上也没有"更新版本"的入口**：更新是进主界面之后的事（第 10 节），门禁期间出现在这里只会让人误以为"先更新再安装"也行。

**「当前步骤」与「正在看哪一步」是两件事**（t43 新增，冻结 §0.3 的 R-29 / R-30）：

- **当前步骤**（`currentStepId`）：判定的结论，纯规则、界面不自己判 —— 上面那段不变；
- **正在看哪一步**（视图）：正文实际画出来的那一步。两者**默认一致**（判定一变，正文跟着走）；
  用户在左轨上点了某个**走过的**节点之后**钉住**，正文就停在那一步，判定再前进也不动它。

**左轨节点能点什么**（R-28，替换视觉 §4.2 原来那句「不可点」）：

| 节点状态                                   | 可点                                                       | 点了会怎样                                                                            |
| ------------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `已完成` / `已跳过`                        | ✓ 可聚焦，`Enter` / `Space` 同鼠标，按阅读顺序排在卡片之前 | 正文切到这一步，画**只读回看卡**（下面那条）；已经是在看的那一步时 = 「回到当前步骤」 |
| 当前步骤（`待办` / `进行中` / `没测出来`） | ✗                                                          | —（它就是正文，点了也没有别的去处）                                                   |
| 还没轮到的后续步骤                         | ✗ 不进 `Tab` 顺序                                          | —（保持 R-01 ② 的原意：不做一排点不动的灰卡）                                         |

**只读回看卡**（R-29）：一句话说清**这一步已经完成，不用再做什么**（`已跳过` 的写**这一步你选择了跳过**）

- 判定给出的那几句事实（路径 / 版本，直接沿用 `step.detail` 的原文）+ 一个主按钮
  **回到当前步骤（<当前步骤标题>）**。**卡里没有任何安装 / 跳过动作** —— 回看时屏上仍然只有一件事可做。

**判定前进时不把用户推走**（R-30）：钉住期间判定前进（当前步骤往后挪，或三步全部完成、门禁放行），
正文留在原地，只在卡片上方多一行：**下一步（<标题>）也已经就绪了** + 「继续 →」；三步都完成时是
**三步都完成了** + 「看看结果 →」。点它 = 回到当前步骤 / 进放行页，并同时解除钉住。

离开条件（三条）：

1. 三步全部完成（或可跳过的已跳过）→ 门禁放行，**原地变成放行页**（不自动跳走，需求文档 5.3）；
2. 用户点逃生口 → `escaped`；
3. 当前步骤判定为「测不出来」导致门禁其实是 `unknown` → 直接进主界面 + 黄条 + 向导入口。

### 2.5 门禁层显示期间的键盘与快捷键

| 输入                           | 行为                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------- |
| `Ctrl` + 数字键 / `⌘` + 数字键 | **不生效**（切页捷径在门禁层显示期间被挡住，与启动锁期间一致）                           |
| `Ctrl+R` / `⌘R`                | 不生效（重载会把用户拽回检查中，且门禁层正在显示时重载没有意义）；**逃生口点了之后恢复** |
| `Tab` / `Shift+Tab`            | 只在门禁层内部循环（背景里的左栏与页面**不可聚焦**，见 2.10）                            |
| `Enter` / `Space`              | 触发焦点按钮                                                                             |
| `Esc`                          | **门禁层可见时等于逃生口**（调 `escapeGate()`，见 0.4 第一行）；其余情况什么都不做       |

### 2.6 `unknown`：没测全（**不挡人**）

进入条件：没有明确缺失，但至少一个步骤"测不出来"（探测失灵 / 受限环境 / 报告整体出错）。**这种情况一律放行** —— 「我们的探测失灵」不能变成用户的牢门（需求文档 4.2、5.3）。

界面行为：

1. **不显示门禁层**，直接进主界面；
2. 主界面顶部常驻一条黄条（不可关闭，沿用控制台页 `.banner` 的位置与形状）：
   - 正文：**这一轮没测全（原因：<原因>），下面的结论可能不准。**
   - 右侧两个按钮：**重新检测** / **打开环境向导**；
3. 环境自检页顶部出现「重新打开环境向导」（2.8 第 2 条）；
4. 黄条在**下一次报告里没有 `unknown` 步骤**之后自己消失（判据来自报告，不是来自"向导走过没有"）。

### 2.7 逃生口

| 项       | 规格                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 位置     | 门禁层**底部常驻**（不是超时后才出现，不在二级菜单 / 折叠区里，不需要滚动才能看到）                                        |
| 形态     | 一个普通按钮，**允许聚焦**（键盘用户必须能 Tab 到它）                                                                      |
| 文案     | **先进入界面（环境还没准备好，我稍后自己处理）**                                                                           |
| 可点性   | **永远可点**。不因相位、不因探测失败、不因安装动作正在跑、不因互斥锁被占而禁用，也不被任何"只有某种情况下才显示"的条件挡住 |
| 代价     | 无。点了不改任何东西、不写任何文件、不改变判定、不留持久化痕迹（**不是设置项**，下次启动照旧判定）                         |
| 可重复   | 逃生 → 回向导 → 再逃生，永远有效；逃生不是一次性豁免                                                                       |
| 点完之后 | 立刻收起门禁层（不等待、不弹二次确认），进入主界面，并按需求文档 5.2 触发一次自动启动（若开着自动启动且本轮没试过）        |

**为什么不做二次确认**：逃生口是一个明确的按钮、文案里已经写清后果，再加一层确认只会让"我就是要进去看日志"的人多点一次。**为什么不做成链接样式**：它是这个状态下唯一能前进的出口，视觉规格可以把它画得不抢眼，但**它必须仍然是一个可聚焦的按钮**。

### 2.8 逃生之后：三条回到向导的路

用户走了逃生口之后，界面上要同时具备这三条路（缺一条就会有用户找不回来）：

1. **控制台页顶部的常驻横幅**（不可关闭，沿用 `.banner` 的形状与位置）：
   - 正文：**运行环境还没准备好：<第一步没完成的>** —— `<…>` 填的是当前步骤那句"为什么它还是缺的"（结论由判定给出，界面不自己写）；
   - 右侧按钮：**继续配置** → 重新显示门禁层（直接回到挡住页的当前步骤）；
   - 这条横幅**只在门禁状态是 `blocked` 时出现**，环境好了就自己消失。
2. **环境自检页顶部**：「**重新打开环境向导**」按钮。点击 = 重新显示门禁层（同样落在当前步骤）。它不写盘、不改变任何判定，只是把覆盖层再显示出来。
3. **环境自己变好的时候横幅自动消失**：用户在界面里自己把环境修好了（例如去命令行装了 Node）并点了一次「重新检测」→ 判定变成放行 → 横幅消失。**判据来自报告，不是来自"向导走完过没有"**。

**三条路的共同点**（t43 / R-31）：都把门禁层重新显示出来，并**停在向导里** —— 判定即使已经是 `open`
也显示放行页，不会「一闪就没了」。离开向导只有三个**显式**动作：「进入 DSH Console」、`Esc`（= 逃生口）、
点底部那条逃生口。判定是 `unknown` 时仍按 2.6 不挡人（层收起 + 黄条）：那一屏的意思是我们没测全，
不该假装成结果页。

### 2.9 「重新检测」与互斥

- **重新检测**：任何时刻可点（除了"有一个会改系统的动作正在跑"时 —— 那时禁用，避免用户以为界面卡住却其实是动作在跑）。
  - 点击后进入 `checking` 的视觉态（进度指示 + **正在检查这台电脑上的运行环境**），但**不收起门禁层**、**不清空正在显示的结果**，只是把结论区标成"检查中"；
  - 报告回来后原地更新步骤状态。**判定往前挪了不等于正文跟着挪**（t43 / R-30）：没钉住时正文跟到新的当前步骤；
    钉住时正文留在用户正在看的那一步，并出一行「下一步也已经就绪了」的提示（2.4）。
- **互斥**（需求文档 11.4）：同一时刻**只能有一个会改系统的动作**在跑（装 Node / 装 pnpm / 装 dsh / 更新 Node / 更新 pnpm）。界面表现是**其它动作的按钮直接禁用**（不写"点了之后回一句已经在跑"），并且被禁用的按钮上要有一句说明（`title`）：**正在执行上一步的操作，完成后按钮会自动恢复**。
- **逃生口不受互斥影响**（2.7）。

### 2.10 背景不可聚焦

门禁层显示期间，**背景里的左栏、页面、状态栏里的可聚焦元素必须真的不可达**：

- 门禁层用自己的容器承接焦点（背景在可达性上视为不可交互）；
- 两条可选做法（任选其一，但**必须让 `Tab` 走不进背景**）：把背景整体标成不可交互；或把门禁层声明成一个模态对话框并让焦点在它内部循环；
- 背景里的按钮**不要**只是"看起来灰了"却仍能被 `Tab` 到（那会让键盘用户按下一步就消失了）。
- 门禁层收起之后（放行 / 逃生 / 判定为不挡），背景必须**立刻恢复**可聚焦：撤销上述处理，不留遮罩、不留全局键盘拦截。

### 2.11 放行页（原地变成结果页）

进入条件：门禁从 `blocked` 变成放行（三步完成或已跳过）。

界面行为：

1. **不自动跳走**（需求文档 5.3 的硬要求：修复输出与复检结论要让人读得完）；
2. 标题变成：**运行环境已经就绪**；
3. 副标题：**三步都完成了（可跳过的项按你的选择处理），现在可以进入了。**
4. 主按钮（**默认焦点**）：**进入 DSH Console**
5. 次操作：**再看看环境自检** → 收起门禁层并切到环境自检页（左栏第 8 项）；
6. 若第二步是被跳过的，这里多一行：**pnpm 这一步你选择了跳过：插件页的装 / 卸 / 升级还用不了，以后可以回来补上。**
7. 点「进入 DSH Console」→ 收起门禁层 → 走阶段一的正常流程（自动拉起 dsh → 就绪后按既有设置打开 Harness、进全屏）；
8. 门禁层收起后**不再出现**（本次运行）。
9. **从环境自检页 / 常驻横幅「重新打开环境向导」进来时也显示这一屏**（t43 / R-31）：即使这一轮没挡过人
   （环境本来就够用）也停在放行页等用户自己走 —— 「重新打开向导」的目的就是看这一屏。健康机器**首轮**
   依旧什么都不显示（没有"结果"可看，一张全屏层只是打扰）。

### 2.12 `blocked` 与自动启动的先后（首次启动的可见结果）

| 场景                         | 屏幕上发生什么                                                                                                                                                                                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 缺东西（`blocked`）          | **不出现启动锁**；直接是「正在检查」→ 挡住页。用户不会先看到一次失败的启动再听解释（需求文档 5.2 的顺序要求）                                                                                                                                                                                |
| 从逃生口离开                 | 收起门禁层 → 自动启动照旧（设置 `autoStart` 开着才做），但**不显示启动锁**（t44 / R-32）：用户刚说了「环境还没准备好，我稍后自己处理」，再按住他等是不礼貌的。启动进度照既有那一套看（状态栏 + 控制台页 + 事件日志）                                                                         |
| 放行页点「进入 DSH Console」 | 收起门禁层 → 自动启动**显示启动锁**（t44 / R-32）：写的就是启动时那套（「正在启动 dsh 服务」/「已等待 N 秒 · 就绪后自动打开 DeepSeek Harness 并进入全屏」/「不等了，先进入界面」），解锁条件也一样。**没有等待就不上锁**：dsh 已经在跑、或这一轮只是接管外部实例时自动启动是空操作，锁不出现 |

两条路都会自动启动（不变）；差别只在**要不要按住用户等**。锁仍是单向状态机：`armAfterGate()` 是
「向导结束 → 自动启动」这一轮唯一的开锁许可（5 秒窗口，见冻结 §0.4 的 R-32），**不是**「每次状态变化重新判定」。

## 3. 逐步引导：三步的公共形状

### 3.1 每一步都由六块组成（顺序固定）

| #   | 区块   | 内容                                                                                    |
| --- | ------ | --------------------------------------------------------------------------------------- |
| 1   | 标题   | 「第 N 步：<做什么>」                                                                   |
| 2   | 为什么 | 一句话说清这一步不做会怎样（原样文案见第 4~6 节）                                       |
| 3   | 事实行 | 这一步用到的那几项自检结论（人话 + 事实：路径 / 版本），以及「展开看详情」              |
| 4   | 主操作 | 一般只有一个（「安装」或「开始」），角色是 `primary`                                    |
| 5   | 次操作 | 出路：可跳过步骤的「先跳过这一步」、Node 的「我想自己去官网下载安装」、失败时给的那几条 |
| 6   | 确认区 | **默认收起**，点主操作后**原地展开**（不弹原生对话框、不跳页）；标题固定为「将要执行」  |

### 3.2 确认区里必须出现的六件事

1. **将要执行**：命令原文或安装器名（主进程给的那份，界面只显示）；
2. **下载来源**：主机名（正文只给主机名，完整地址放"详情"里，可复制）；
3. **会改到哪里**：目录或"npm 的全局目录"；
4. **要不要联网**；
5. **要不要管理员权限**：需要时给一句用户语言 —— **接下来 Windows 会问你一次是否允许安装（管理员权限）**；
6. **一句风险说明**：这一步会覆盖 / 新增什么、会不会影响别的东西。

确认区底部两个按钮：**开始**（`primary`，默认焦点）与 **取消**。**用户必须点「开始」才会动系统**（不静默安装、不静默要管理员权限、不静默换源）。

### 3.3 三步各一句话为什么（原样文案）

| 步骤 | 标题                 | 为什么                                                            | 可跳过 |
| ---- | -------------------- | ----------------------------------------------------------------- | ------ |
| 1    | 第一步：安装 Node.js | **没有它 dsh 起不来，也无法安装后面的东西**                       | 否     |
| 2    | 第二步：安装 pnpm    | **装插件、卸插件、升级插件都要用它**                              | 是     |
| 3    | 第三步：安装 dsh     | **dsh 是 DSH Console 要启动的服务本体；没有它界面里什么都做不了** | 否     |

**不可跳过的两步（Node / dsh）上不出现任何"跳过"字样的按钮**，也不出现"以后再说"。这是需求的硬门禁，不是文案风格问题。

### 3.4 步骤展开详情的规则

- 默认**收起**；点击「展开看详情」才显示自检项的原文内容；
- 详情里可以出现路径、变量名、命令原文这类技术细节（需求文档第 3 节的词表规则：技术细节只在用户点开的区域里）；
- 详情**不折叠**成 tooltip（键盘用户读不到 tooltip）。用可展开的行内区域，`Enter` 能开、`Esc` 能关（0.4）。

## 4. 第一步：安装 Node.js

**进入条件**：门禁挡住，且当前步骤是第 1 步（Node 判定为"缺东西"）。

### 4.1 元素与文案（从上到下）

1. 标题：**第一步：安装 Node.js**
2. 为什么：**没有它 dsh 起不来，也无法安装后面的东西**
3. 事实行：**这台电脑上没有找到 Node**（来自自检结论原文）+「展开看详情」
4. 选择区（**单选**，两个选项，默认选中一个）：

| 选项             | 标题                                                   | 说明行                                                                                        | 默认                |

| 用版本管理器安装 | **用版本管理器安装（不用管理员权限，可以装多个版本）** | **先装一个版本管理器（nvm），再用它装 Node；不会动系统里原有的 Node，之后可以随时切换版本。** | 机器上已经有 nvm 时 |

5. 主操作：**安装**（`primary`。本步的主操作就是"开始装"，`Enter` 直接开确认区）

   **装好之后，其它已经打开的终端窗口需要重开一次，才会用上新装的 Node。**
8. 逃生口（2.7 常驻，不再重复）

**t29 修订（VM-14 / VM-15）：第 4 条改规则，并新增"档位"这一件必须看得见的东西。**

**4-a 方法不再"默认选一条"，而是跟随这份 Node 的真实归属**（判据在需求 §7.7，界面**不许**自己判路径）。
**注意最后两行（VM-16 修订，t29 的四条只讲"默认"没讲"能不能改"，被实现塌缩成了"不给选"）**：**一份 Node 都没有时同样是"两个选项都列出来"**，
默认只是**预选**——用户必须能改；这两行的事实行要**写出方法**（不只是档位）：

| 这台机器上的情况                                          | 选择区长什么样                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 找到的 Node 是**版本管理器管的**                          | **不给单选**：一行事实 **这份 Node 是版本管理器（nvm）管的，所以我们也用它来装 / 换。**（主操作照旧是「安装」）                                                                                                                                                                    |
| 找到的 Node 是**官方安装包装的**                          | **不给单选**：一行事实 **这份 Node 是官方安装包装的，所以我们也用官方安装包把它换到同一个位置。**                                                                                                                                                                                  |
| **找到了一份 Node，但归属判不出来**（含归别的版本管理器） | **两个选项都列、一条都不预选**（用户必须显式选一条）；上面加一句事实 **我们认不出这个 Node 是怎么装的。** 两个选项各带需求 §7.9 第 4 条那句并存风险                                                                                                                                |
| **没找到 Node**，但机器上已有一个可辨认的版本管理器       | **两个选项都列**，默认**预选**「**用版本管理器安装**」（预选 ≠ 不能改）；**事实行必须写出方法**：**这台电脑上还没有 Node，但已经装了一个版本管理器（nvm）：默认用它装，之后可以随时切换版本。也可以改用官方安装包（会问一次管理员权限，装到系统默认位置）。**                      |
| **没找到 Node**，也没有可辨认的版本管理器                 | **两个选项都列**，默认**预选**「**直接安装官方版本**」（既有默认）；**事实行必须写出方法**：**这台电脑上还没有 Node：默认用官方安装包装到系统默认位置。也可以改用版本管理器（不用管理员权限、可以装多个版本）。**；确认区还要固定一行重述（§4.3 第 8 条）—— 有默认**不等于**默默装 |

**这两行的并存风险句**（需求 §7.9 第 4 条那句）**不出现**：这台机器上还没有 Node，选哪条路都是它的**第一份**，不存在"两份谁生效"的问题。

**4-b 档位必须看得见（VM-15 的直接修法）**：与"方法"**同级**多一个**档位选择**（可聚焦的两选一，不是一行小字按钮）：

- 文案：**最新稳定版**（默认）/ **最新当前版**，各带一句差异说明（稳定版：发布更久、坑更少；当前版：追最新特性，可能还没进入稳定期）；**不写"LTS"这类术语**；
- **位置**：在**选择区里**（进入第一步就能看到），**不是**藏在确认区里的一个小按钮 —— 现状是一行小字按钮，用户根本没意识到自己切到了「当前版」；
- **确认区里固定有一行「版本档位」**重述它（形状：`最新稳定版`，换过档时同时给出目标版本号）；
- **一旦装过一次，不记住上次选了哪一档**（照 §4.2 最后一条的纪律：两条路 / 两档对系统的改动不同，不替用户记）；
- 装了**另一档**的版本时，界面要把它说成**换档**而不是升级（见 §10.5 第 5 条）。

### 4.2 两个选项的取舍怎么解释

- **谁是默认**（**t29 推翻** ~~两条路都默认「直接安装官方版本」~~、~~「机器上已经有版本管理器时默认用版本管理器」有意没有实现~~）：
  **默认由"这份 Node 的真实归属"决定**，规则与文案见 §4.1 的 t29 修订 4-a。三条要点：
  ① 归属判得出来时**只给一条路**（不给那个会在机器上留下第二份 Node 的选项）；
  ② **找到了一份 Node 却判不出归属**时**一条都不预选**，由用户显式选，并说清两份并存的后果；
  ③ 没找到 Node 时，按"机器上有没有一个可辨认的版本管理器"给默认（有 → 用版本管理器，没有 → 官方安装包）。
  当年那句"需要**一次新的探测 + 一个契约字段**"**现在做到了**：判据是需求 §7.7，字段是 `EnvDoctorReport.nodeOwner`（需求 §11.2.1）。
- **档位的默认**（t29）：**最新稳定版**（设计规定，不变）。但**更新**不是安装 —— 更新的目标档位**跟随当前档位**（§10.5 第 4 条），
  它的默认值是"已装那一份的档"，不是"最新稳定版"；这两处的默认值**不许共用同一个写死的常量**。
- **差异怎么解释**：不写表格、不写术语（不出现 `PATH` / `NVM_HOME` / `MSI` 这些词），只用选项下面那一句说明讲三件事 —— **要不要管理员权限**、**会不会动原有的 Node**、**能不能装多个版本**。
- **用户能不能改主意**：**能，而且在开始之前随时能改**。切换选项只是换一份确认区的内容，**不动任何东西**。
- **装到一半能不能换**：
  - 还在确认区（没点「开始」）→ 能改；
  - 下载中 → 点「取消下载」回到未开始的状态（系统零改动），然后能改；
  - **已经进入安装阶段（管理员权限询问之后）→ 不能换，也不该换**：安装器已经在跑了，这时两个选项**暂时不能动**，旁边给一句 **正在安装，请等它结束**。装完之后如果这一步仍没完成，选项自然恢复（那时换路是安全的）。
- **每次都重新确认**：**不记住上次选了哪条路**（下一次仍然按 4.2 第一条的默认规则）。理由：两条路对系统的改动完全不同，不适合替用户"记住"。

### 4.3 确认区（点「安装」后原地展开）

固定六件事（3.2）+ 两条本步特有的信息：

1. **将要执行**：安装包名与**具体版本号**（例如「Node.js 稳定版 vX.Y.Z 的官方安装包」——版本号由主进程给，界面不自己拼）；
2. 版本这一档是哪一档：**稳定版** / **当前版**（不许含糊地说"最新版"）；
3. **下载来源**：主机名（详情里给完整地址与「复制」）；
4. **会装到哪里**：目录；
5. **会改什么**：覆盖 / 新增系统里的 Node（两条路的说法不同，见 4.1 说明行）；
6. **要不要管理员权限**：直装 = 要，并给 3.2 第 5 条那句预告；nvm = **不需要管理员权限**；
7. 需要联网：**是**（**例外**：归属 = 版本管理器、且机器上已经有它时，这次**没有任何东西要下载** —— 那几行下载来源 / 安装包名 / 完整性**不出现**，改说一句 **这次不用下载安装包：让版本管理器自己装 Node.js <版本>。**）。
8. **这份 Node 是谁管的**（t29 新增，**必含一行**）：**版本管理器（nvm）管的** / **官方安装包装的**；归属判不出来时这一行换成 **我们认不出这个 Node 是怎么装的。** —— 读的是主进程给的归属字段，界面不自己判路径。
9. **版本档位**（t29 新增，**必含一行**）：值与 §4.1 第 4-b 条的档位控件是**同一个**（换档后两处同时变）；形状 `最新稳定版`，换过档时写成 `最新稳定版（vX.Y.Z）`，并带一句换档说明（§10.5 第 5 条那几句）。

**另外四个条件分支**（都由主进程给的事实决定，界面照实显示）：

- **（官方直装）拿不到官方校验清单**（没有它就无法确认这台电脑的架构有没有安装包，也无法在下载后比对哈希）→ **不给「开始」**（计划照常显示，只是主进程给的是一份"这条路径不能走"的计划），确认区里给一句：
  **没能从官方来源拿到这个版本的校验清单。** 并给出路：**换一个下载源再试** / **打开官方下载页** / **重新检测**。
  这一条**不许**说成「这个版本没有适合这台电脑的安装包」—— 那是网络问题，不是官方的结论（这条在 t13 里定过，见 `docs/env-wizard-freeze.md` 的 R-25/R-27）。
- **（版本管理器旧发布线）没有摘要可校验**（发布资产没有 `digest`）→ 确认区里给一句既有的提示：
  **这次没能校验安装包的完整性。** + **换一个下载源再试**（**默认焦点**） / **仍然继续**。
  这是一条**正常情形**（旧线就是这样），不是错误；**也不许**用发布线里的 zip 校验文件去猜 exe 的哈希。
- **这个安装包没有数字签名** → **只在两种情形出现，计划阶段只在第二种出现**：
  ① 已经下载完、**真的**读到「未签名 / 签名无效」，且用户**没有**在计划阶段确认过（`releaseSigning !== 'unsigned'`）→ 结果区里给「这个安装包没有数字签名，我们没有安装它。」+ 打开官方下载页 / 重新检测（**不安装**）；
  ② 走的是版本管理器那条路、且**发布元数据的自述**是未签名（`releaseSigning === 'unsigned'`）→ 确认区里给「这个安装包没有数字签名，要装吗？」，用户明确确认才继续（依据来自发布元数据，不是读文件，所以计划阶段就成立；**默认焦点给「取消」**）。
  已确认过（②）之后再在下载后读到未签名 → **继续安装**（不重复问）。
  **计划阶段严禁**因为 `signer` 为空就说"没有数字签名"、也**不许**因此多一次确认 —— 那时我们还没读过签名，`null` 只表示"尚未读取"；计划阶段唯一能依据的是 `releaseSigning`；
- **架构不支持**：目标版本没有对应这台电脑的 Windows 安装包（判据 = 同版本的官方校验清单里没有那个文件）→ **不给「开始」**，只给：
  **这个版本没有适合这台电脑的安装包。** + **打开官方下载页** / **换一个版本**（= 换"稳定版 / 当前版"这一档）。

### 4.4 主操作与次操作

| 位置     | 文案                               | 行为                                                             |
| -------- | ---------------------------------- | ---------------------------------------------------------------- |
| 主操作   | 安装                               | 展开确认区                                                       |
| 次操作   | 我想自己去官网下载安装             | 用系统浏览器打开官方下载页；本步状态不变，用户装完点「重新检测」 |
| 确认区   | 开始 / 取消                        | 开始 = 真的动手；取消 = 收起确认区，零改动                       |
| 进度区   | 取消下载 / 不再等待                | 见第 7 节（两种完全不同的语义）                                  |
| 失败之后 | 用版本管理器安装（不用管理员权限） | 只在**拒绝管理员权限**之后出现，作为替代出路（第 8.2 节）        |

### 4.5 等待 / 失败 / 超时

按第 7 节（进度与三种"不再等"）与第 8 节（管理员权限询问的结果）执行。本步另外两条专属：

- **成功**：**Node.js <版本> 装好了，这一项已经变成「正常」。** + **其它已经打开的终端窗口需要重开一次，才会用上新装的 Node。**
- **装完仍然找不到 Node**（复检仍是"缺东西"）：
  **装完了，但我们还没找到 Node。** 出路三条：**重新检测** / **再试一次** / **我想自己去官网下载安装**。
  ~~「重开一次应用」~~ **有意不做**：仓库里没有「重新拉起应用」的 IPC，而用 `location.reload()` 冒充是**误导**
  （重载渲染层**不会**重读系统查找路径）。实现侧是用「装完重读注册表里的用户级 + 机器级 PATH + 已知目录扫描」
  来覆盖这个场景的 —— 所以正常情况不需要重开应用；真的还找不到时，界面给的是上面那三条。
- **版本管理器已经装好、但它一个版本都没有**（客机状态：`node.exe` 是 shim、跑起来**零输出**，它自己的原文是
  `No active Node.js version is configured. Run \`nvm install <version>\` then \`nvm use <version>\`.`）：
这一屏**不是**让用户去终端里选版本，而是**应用自己装**。事实行（门禁层里 `step.detail` 渲染的那一行）要说中这个状态：
**版本管理器已经装好了：这份 Node（<路径>）就在它管的目录里，但它还没有装任何 Node 版本（或者没有选中一个），所以这个 node.exe 现在跑起来没有任何输出**
出路：**点「安装 Node.js」**（走版本管理器那条路，由我们挑一个稳定版装好并切过去） / **重新检测**。
这条出路做到的判据是四步事实，缺一步都不算完成：`nvm install <版本>`（看退出码 + `Installed Node.js …`标记）→`nvm list`核对清单里真出现了它 →`nvm use <版本>`→ 实测`node --version`与`npm --version`**都有输出**。
**不许**把 shim 那句原文转给用户，也不许出现"请到终端里`nvm use`"（VM-13 / F-05 的教训；
模型与完整链路见 [`docs/env-wizard.md`](env-wizard.md) §7.6）。

### 4.6 离开本步的条件

成立任一即离开（并把焦点交给下一步或结果页）：

- 复检结论显示 Node 这一项不再是"缺东西" → 第一步变「已完成」，门禁前进到第二步；
- 复检结论显示 Node 这一项"测不出来"（而不是明确缺东西）→ 门禁降级为放行 + 黄条（2.6），**不把用户留在这一步**；
- 用户点逃生口 → 离开整个门禁。

**不许**用"安装器退出码是 0"当作离开条件 —— 离开条件永远是**复检的事实**。

## 5. 第二步：安装 pnpm

**进入条件**：Node 已完成，且 pnpm 判定为"缺东西"（或此前跳过、现在又回来了）。

### 5.1 元素与文案

1. 标题：**第二步：安装 pnpm**
2. 为什么：**装插件、卸插件、升级插件都要用它**
3. 事实行：**这台电脑上没找到 pnpm** +「展开看详情」
4. 主操作：**安装**（展开确认区）
5. 次操作：**先跳过这一步**
6. 跳过说明（紧挨着次操作，**原样文案**）：
   **跳过之后，插件页的装 / 卸 / 升级仍然用不了（以后随时可以回来补上）。**
7. 逃生口（2.7）

### 5.2 确认区

3.2 的六件事：

- **将要执行**：`npm i -g pnpm` 一类命令原文（主进程给的，界面照显）；
- **下载来源**：默认是系统 npm 配置；**如果用户设置过安装源，这里要写明「本次使用你设置的安装源：<主机名>」**；
- **会装到哪里**：全局 npm 目录；
- **要不要管理员权限**：**不需要**；
- **要不要联网**：**是**；
- 风险说明：会往全局 npm 目录里加 / 更新 pnpm。

### 5.3 npm 本身不可用时

如果报告显示 npm 不可用（这决定"能不能一键装"）：

- **不显示「安装」主操作**（点了必然失败，不给一个注定失败的门）；
- 事实行下面给一句：**这台电脑上的 npm 还不能用，所以没法替你装 pnpm。**
- 给一条可以照着做的命令（可复制）：
  **corepack enable pnpm**
- 仍然保留次操作：**先跳过这一步**（后果照上面那句写）。

### 5.4 跳过：知情选择

- **点「先跳过这一步」不是立即生效的静默操作**：它就地变成一次确认（同一次展开区域，不弹原生对话框）：
  - 文案：**确定先跳过 pnpm 这一步吗？跳过之后，插件页的装 / 卸 / 升级仍然用不了（以后随时可以回来补上）。**
  - 按钮：**确定跳过** / **取消**；
- 确认后：这一步标记为**已跳过**，门禁前进到第三步；
- **已跳过的标记要留在三个地方**：向导的步骤条上（「已跳过」）、环境自检页的那一行（「已跳过」）、以及放行页上那句提醒（2.11 第 6 条）；
- **必须能恢复**：环境自检页里被跳过那一行上给「**把这一步加回来？**」；点了之后该步骤回到"待办"，下次进向导会停在这一步。恢复本身只改那一个设置项，不做别的任何事。

### 5.5 失败出路（对照需求文档 6.3）

| 失败                     | 界面上给什么                                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 网络不通 / 连接超时      | 归纳过的一句（认不出来就给原文尾部）+ **换一个安装源** + **打开官方下载页** + **重新检测** + **先跳过这一步**                        |
| 装到一半说找不到包       | 认得出就点名说缺的是哪个包（**常常不是你写的那个包，而是它依赖链上的**）；认不出来就说「安装源上没有找到需要的包」+ **换一个安装源** |
| 权限不足                 | **装不进全局目录。** + 一条可以照着做的命令（可复制）+ **先跳过这一步**                                                              |
| 安装源指向已停服的旧镜像 | 单独点出来：**你设置的安装源是一个已经停止服务的旧镜像。** + **换成 <现在可用的那个主机名>**（不静默替换）                           |
| 认不出来                 | 只说事实（原文尾部），不编原因；给「先跳过这一步」与「重新检测」                                                                     |

### 5.6 离开本步的条件

- 复检显示 pnpm 不再是"缺东西"（`warn` 也算完成）→ 变「已完成」，前进到第三步；
- 用户确认跳过 → 变「已跳过」，前进到第三步；
- 逃生。

## 6. 第三步：安装 dsh

**进入条件**：Node 已完成，且 dsh 这一项判定为"缺东西"。

### 6.1 元素与文案

1. 标题：**第三步：安装 dsh**
2. 为什么：**dsh 是 DSH Console 要启动的服务本体；没有它界面里什么都做不了**
3. 事实行：**这台电脑上没找到 dsh** +「展开看详情」
4. 主操作：**安装**（展开确认区）
5. **没有跳过**（不可跳过，需求文档 4.1）
6. 逃生口（2.7）

### 6.2 确认区

同 5.2 的六件事，命令是在全局装 dsh 的命令原文（界面照显），**不需要管理员权限**，**要联网**。

### 6.3 完成判据要在界面上说清（"找得到"不等于"跑得动"）

- 这一步的完成**必须同时满足两件事**：找得到 dsh，**并且实测跑得动**（有输出）。只看"找得到"会放行一台其实跑不动的机器（需求文档 4.1：某些 Node 版本下 dsh 会"退出码 0、零输出"地静默退出）。
- 所以事实行要显示两条结论（都用人话）：
  - **dsh 本体**：找到 / 没找到；
  - **dsh 能不能跑**：能跑 / 跑不动 / 这一轮测不出来。
- 装完之后如果"能跑"这一项仍是"跑不动"或还没结论 → **这一步不算完成**，留在本步并给下面的出路。

### 6.4 失败出路

| 失败                 | 界面上给什么                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 网络 / 权限 / 安装源 | 同 5.5（含**换一个安装源**、**重新检测**）                                                                        |
| 装完了但跑不动       | 标题一行：**dsh 装上了，但在这台电脑上跑不起来。** + 出路两条（见下）                                             |
| 跑不动的出路 ①       | **换一个 Node**：~~用版本管理器装一个符合要求的版本并切换过去~~（做这一步的入口就在本页，不再让用户自己去命令行） |

**t7 标注（出路 ① 的方法与档位）**：这一条**不再固定走版本管理器** —— 它是一次 `mode === 'install'` 的动作，
所以方法与档位都按同一套规则走：**方法跟随这份 Node 的归属**（版本管理器管的走版本管理器、官方安装包装的走官方安装包
——后者"换一个 Node"就是把它换到同一个位置，见需求 §7.8），**归属判不出来时两条路都列、一条都不预选**；
**档位用安装的设计默认（最新稳定版）**。要提醒的是：**这个默认可能正好跨档**（机器上装的是当前版、出路①装的是最新稳定版），
所以这一屏的确认区也要按 §10.5 第 5 条那几句说清 —— **跨档就叫「换档」、目标更低时要写出「版本从 vX 降到 vY」**，
不许因为"它是安装、不是更新"就把它当一次普通安装混过去（这正是冻结 §1.2 R-09 当初"固定走 nvm、不给直装"被 t29 取代的地方）。
| 跑不动的出路 ② | **在设置里写死一条能跑的启动命令** → 跳到设置页对应的输入框（既有出路，界面照旧） |

**"换一个 Node"必须是引导的一部分，不是一句甩给用户的话**：点它之后要走一次和第 4 节一样的确认区（同一个安装通道、同一个"将要执行"格式），装完回到本步复检。

### 6.5 离开本步的条件

- 复检同时满足"找得到"与"跑得动" → 这一步完成；
- **三件都完成或已跳过 → 门禁放行 → 原地变成放行页**（2.11）；
- 逃生。

## 7. 执行中：进度、等待与三种"不再等"

### 7.1 一条通道，两种语义

| 阶段                         | 界面上的按钮                                     | 按下去的后果                                                           |
| ---------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| 准备 / 下载中                | **取消下载**                                     | 停止下载、删掉临时文件，**系统上没有任何改动**，回到确认区之前的状态   |
| 下载完成 → 校验中            | **取消**（同「取消下载」；此时也只动了临时文件） | 同上                                                                   |
| 安装中（管理员权限询问之后） | **不再等待（安装可能还在后台进行）**             | **只停止等待，不停止安装**。界面进入"不确定"态，引导用户点「重新检测」 |
| 复检中                       | 无按钮（很短）                                   | —                                                                      |

**硬要求**：安装阶段**没有"中断"这种按钮**，界面上也不出现"中断"两个字（需求文档 8.4：把安装器杀在半路会留下一个半装的 Node，比不装更糟）。阶段一旦从下载跨到安装，按钮**必须当场换成「不再等待（安装可能还在后台进行）」**，并给一句后果说明：

**安装已经在进行，这里只能停止等待，不会去停止安装。装完之后点「重新检测」看结果。**

### 7.2 进度区（下载 / 校验）

四行内容：

1. **正在下载 Node.js <版本>…<百分比>%**（百分比来自主进程，界面不自己算）；
2. 已下载 / 总大小与速度（可有可无，由视觉规格决定是否显示）；
3. 校验时换成：**正在校验安装包完整性**；
4. 原始输出区（流式原文照贴，默认收起、可展开 —— 与既有的"一键修复"输出区同一种形状）。

**校验失败**：**完整性校验没通过，已删除，没有安装任何东西。** + 出路：**换一个下载源再试** / **打开官方下载页** / **重新检测**。

### 7.3 等待管理员权限询问时的界面

- 进度区的状态行：**正在等待安装程序**（不写"等待权限询问"之类的内部说法）；
- 一句提示：**接下来 Windows 会问你一次是否允许安装（管理员权限）。按它的提示选择就好。**
- 按钮：**不再等待（安装可能还在后台进行）**；
- 顶栏不受影响（窗口能拖、能关；关掉应用**不会**杀掉安装器，见 7.4）。

### 7.4 「不再等待」之后

- 界面立刻离开"进行中"的姿态，进入结果区的一条**未确定**结论：
  **我们不等了：安装可能还在后台进行，请按它自己的提示把它做完，做完点「重新检测」。**
- 此时**不给出"成功"或"失败"的结论**（我们不知道）；
- 保留「重新检测」与「打开官方下载页」两条出路；
- 互斥锁**在这个时刻释放**（用户可能按它的提示继续在系统里操作）。等待中的安装器我们**不去杀、也不去追**（需求文档 8.4：一旦开始就不再杀）。

### 7.5 三步各自的"进行中"样子（同一套骨架，只换词）

不管在哪一步，进行中的界面都是同三块：**状态行（一句人话）+ 进度或输出 + 一个明确的按钮**。区别只在词：

| 步骤        | 进行中的状态行                                                                                             | 收尾成功                                                           | 收尾失败（举第一条出路）                           |
| ----------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 1 安装 Node | **正在下载 Node.js <版本>…<百分比>%** → **正在校验安装包完整性** → **正在等待安装程序** → **正在重新检测** | **Node.js <版本> 装好了，这一项已经变成「正常」。** + 重开终端那句 | 按第 7.6 节那一整张表（网络 / 权限 / 校验 / 其它） |

两条通用规则：

- **进度只在能算的时候给**（下载有百分比、npm 安装只有流式输出）；**算不出来就不画进度条**，用输出区 + 状态行代替，不要给一个假装在走的条（既有模块的教训）。
- **每一步的"重试"都在原地**：点「再试一次」等于重新展开同一份确认区，**不重新走一遍前面的步骤**。

**三条与签名 / 校验有关的补充**（t13 的裁决，语义以 `docs/env-wizard-freeze.md` 的 R-25 / R-26 / R-27 为准）：

- **第 5 条与第 6 条不要混**：第 5 条是官方直装的清单取不到（网络问题 → 不给「开始」，也判不了架构）；第 6 条是版本管理器**旧发布线本来就没有摘要**（正常情形 → 可以让用户确认后继续）。

管理员权限**只由安装器自己触发**：应用启动不弹、探测不弹、打开向导不弹、点开确认区也不弹。我们只做两件事 —— 提前预告（3.2 第 5 条）与**用复检事实说话**。

### 8.1 三种结果对照

| 结果       | 用户在界面上先看到什么                   | 我们观察到什么                        | 界面文案（原样）                                                                     | 可做的下一步                                                            |
| ---------- | ---------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **拒绝**   | Windows 那个询问，用户点了"否"           | 安装器退出（非零 / 被取消性质的编号） | **你拒绝了管理员权限，这台电脑上什么都没改。**                                       | 就地给 **改用不用管理员权限的方式安装**（走版本管理器那条路）+ 重新检测 |
| **取消**   | Windows 那个询问，用户点了"取消"或关掉它 | 与上一条可能完全相同                  | **安装没有完成，这台电脑上什么都没改。**                                             | 重新检测 / 再试一次 / 打开官方下载页                                    |
| **等太久** | 我们主动放弃等待（**不杀安装器**）       | 我们不给出任何结论                    | **我们不等了：安装可能还在后台进行，请按它自己的提示把它做完，做完点「重新检测」。** | 按安装器自己的提示做完 → 重新检测 / 打开官方下载页                      |

### 8.2 两处细节

- **拒绝之后「改用版本管理器安装」是按钮，不是一句建议**：点了就走第 4.1 节那条路（同一个确认区格式，并说清"不用管理员权限"）。用户不需要自己去理解两条路的差别。
- **版本管理器那条路如果也弹了一次权限询问**（它可能为注册事件源弹一次）：用户拒绝也**不影响功能**，所以我们**继续往下走并复检**，而不是报失败。界面上不要为这一次拒绝显示任何错误（需求文档 9.1）。

## 9. 下载来源、网络与受限环境

### 9.1 来源控件放在哪、长什么样

- **位置**：环境自检页（左栏第 8 项）里一个独立的小面板，标题 **安装下载来源**。**只在这一处**给控件（设置页不给同一个控件，原因见 10.3）。
- **控件**：一个文本输入框（可编辑）+ 一句说明：
  **留空 = 从官方地址直接下载。填了就用你填的那个地址下载，只影响我们自己发起的下载，不改这台电脑上的任何配置。**
- **改完要保存才生效**：输入框旁边有一个「保存」按钮（确认区里显示的永远是**已保存的那个来源**）；有未保存的改动时，输入框旁边说一句 **改了还没保存**。
- **生效时可见**：确认区里始终显示当前用的是哪个来源（主机名）；填了之后确认区多一句 **本次使用你设置的安装源：<主机名>**。
- **不静默换源**：下载失败**不会**自动重试另一个源；想换源只能由用户改这个输入框并保存，或在失败结果里点那条明确的出路。
- **输入框的键盘行为**：`Tab` 可到、可编辑、`Enter` 不提交（它不是一个表单）；「保存」才是提交动作。

### 9.2 内网 / 完全连不上外网

- 不假设有外网，也不假设有代理：下载失败时给的两条路是 **填一个内部源**（跳到 9.1 那个输入框）与 **自己装好再重新检测**。
- 文案不许写成"失败"，要写成可以绕过去的事实：
  **这台电脑连不上外网，所以这次没法自动下载。你可以填一个内部可用的下载来源，或者自己装好之后点「重新检测」。**

### 9.3 旧镜像的单独提示

用户设置的安装源指向已经停止服务的旧镜像时，界面上**单独点出来**（不与其他失败混在一句里），并给一个**可点的替换建议**（点了才替换，不静默替换）。

## 10. 与「环境自检」页的关系

### 10.1 那仍然是同一页

- 左栏第 8 项（`Ctrl+8` / `⌘8`），**不新增页面、不新增第 10 项**。向导是**覆盖层**，不是第 10 个页面。
- 自检页始终可用：逃生的用户、判定为"没测全"的用户、环境本来就没问题的用户，都从这里看结论。

### 10.2 自检页上新增的三样东西

| 新增                     | 位置                                       | 文案                                                                                                                                              |
| ------------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 回到向导                 | 页面顶部工具条（与既有的「重新检测」并排） | **重新打开环境向导**                                                                                                                              |
| 更新入口（Node）         | 找到 Node 的那一行右侧                     | **更新 Node.js**                                                                                                                                  |
| 更新入口（Node）**不给** | 归属判不出来的那一行（同一行的位置）       | 不给「更新」：给 **打开官方下载页** + **重新检测**，并写明 **我们认不出这个 Node 是怎么装的，所以不会替它做自动更新。**（t29，需求 §7.7 第 3 条） |
| 更新入口（pnpm）         | pnpm 可用那一行右侧                        | **更新 pnpm**                                                                                                                                     |
| 已是最新                 | 同上两行的按钮态                           | **已经是最新版（<版本>）**（禁用态，不给一个点了没反应的按钮）                                                                                    |
| 跳过的步骤恢复           | 被跳过的那一行                             | **已跳过** + **把这一步加回来？**                                                                                                                 |
| 安装下载来源             | 页面里一个独立小面板                       | 见 9.1                                                                                                                                            |

### 10.3 与向导的重复表达：怎么避免

两处**不许**表达同一件事，分工如下：

| 这件事             | 归谁                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| "环境行不行"的结论 | **自检页**（八项逐条事实）。向导只显示**与三步有关的那几项**，且用的是同一份报告的结论               |
| "该装什么、怎么装" | **向导**。自检页上缺失项给的是既有的"一键安装"与一句可以照着做的命令（可复制），**不再重复引导流程** |
| "更新版本"         | **自检页**（向导里没有更新入口 —— 门禁期间还没到"更新"这个阶段）                                     |
| "跳过 / 恢复跳过"  | 向导做选择、自检页做**恢复**（选择本身不在自检页做）                                                 |
| "下载来源"         | 只有 9.1 那一处控件                                                                                  |

### 10.4 向导走完（或逃生）之后，自检页长什么样

- 结论区**照旧**：八项一行一行的现状与结论；向导不改变它、也不把它藏起来；
- 顶部多一个 **重新打开环境向导**；
- 被跳过的行上有「已跳过」与「把这一步加回来？」；
- 找不到 / 不可用的行上，既有的「一键安装 pnpm / dsh」照旧（阶段一能力，不重做）；
- 点「重新检测」后：结论更新，**同时**更新向导的步骤状态（同一份报告），以及 2.8 第 1 条那条横幅的显示与否。

### 10.5 版本更新的入口与确认流程（需求文档第 8 节）

**入口**：只在自检页，只在对应项**可用**时出现（缺失时那一行给的是"安装"，不是"更新"）。

**t29 补（VM-14）：入口出不出现，由"这份 Node 是谁管的"决定**（界面直接读报告里的归属字段，**不许**自己判路径）：

| 归属（报告给的事实）               | 那一行的右侧                                                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **版本管理器（nvm）管的**          | **更新 Node.js** —— 我们知道该用谁去更新它（用它自己的版本管理器，见下）                                                                         |
| **官方安装包装的**                 | **更新 Node.js** —— 用官方安装包装回它自己的位置                                                                                                 |
| **认不出来**（含归别的版本管理器） | **不给「更新」**：给 **打开官方下载页** + **重新检测**，并写明 **我们认不出这个 Node 是怎么装的，所以不会替它做自动更新。**（需求 §7.7 第 3 条） |

> **这条就是 VM-14 的界面对应物**：现状是无论机器上这份 Node 归谁管，点下去都走官方安装包 → 在已经被版本管理器管的机器上
> 又装一份到 `C:\Program Files\nodejs`，之后 `node` 用哪一份只看系统查找路径里谁在前。

**确认流程**（点「更新 Node.js」/「更新 pnpm」之后，**页内展开确认区**，不弹原生对话框）：

1. 标题：**将要执行**；
2. **「当前版本（档位）→ 目标版本（档位）」并排显示**（形状：`v26.9.0（当前版） → v26.10.1（当前版）`）。**档位判不出来时那一半写「档位未知」** —— 不许省略、不许猜（需求 §8.5 第 1 条）；
3. **必含一行「这份 Node 是谁管的」**：**版本管理器（nvm）管的** / **官方安装包装的**（与入口的判据是同一个事实）；
4. **目标档位跟随当前的档位**：「更新」**不带档位意图**；要换档只能点确认区里那个**显式的档位控件**（形状与 §4.1 第 4-b 条那个一模一样 —— 选中的那一档同时决定动作名与文案）；
5. **「换档」与"版本变低"的说法（硬要求，需求 §8.5 第 3、4 条）**：
   - 目标档位与当前档位**不同**时：这个动作的名字是 **换档**，确认区的主按钮写成 **换成稳定版** / **换成当前版**，**不许**叫「更新」；
   - **目标版本号低于当前版本号**时，确认区必须多一句事实（两个版本号都来自计划）：
     **这会把现在这份 Node 换成<档>，版本从 vX 降到 vY。**
   - 目标版本号更高但跨档时，同样叫换档，写成 **版本会从 vX 变成 vY，档位从<旧档>换到<新档>。**；
   - **目标版本 == 当前版本**（同档且已是最新）：**不给确认区、也不给可点的按钮**，按钮位置直接是读数态 **已经是最新版（<版本>）**（不可聚焦、不可点，不是 `<button disabled>`）；
   - **当前档位判不出来**时：**不替用户选档** —— 确认区让用户**显式选一档**（选完即为一次显式的换档动作），并写明 **我们判不出这份 Node 属于哪一档。**；
   - **跨档有两个来源，两处都要照本节说**（t7）：① 用户在这个档位控件上显式选；② **别处的动作按设计默认正好跨档** ——
     向导第三步的「换一个 Node」是一次 `install`（默认"最新稳定版"），在**装着当前版**的机器上它就是一次跨档、而且目标更低。
     所以那一屏的确认区同样要写「换成稳定版」与「版本从 vX 降到 vY」，**不许**因为"它不是『更新』"就把换档那几句省掉。
6. 「更新 pnpm」的确认区多一句：**就是给这台电脑上的 pnpm 装最新版，不改别的东西。**
7. 「更新 Node.js」的确认区必须包含（两条都是需求文档 8.3 的硬要求）：
   - **更新会先停掉正在运行的 dsh，更新完再问你要不要重新启动它。**（仅当 dsh 是本应用启动且正在跑）
   - **这台电脑上可能还有别的程序在用这个 Node。**（不替用户去停不认识的进程）
   - **归属 = 版本管理器时再加一条（t29）**：**这次只动版本管理器自己那份 Node，不会动系统里原来的那一份。** —— 并且**不出现**下载来源 / 安装包名 / 校验那几行（这次没有任何东西要下载，见需求 §7.8）
8. **来源无法判断时不做自动更新**（不是官方默认位置、也不在版本管理器下）：
   **我们认不出这个 Node 是怎么装的，所以不会替它做自动更新。** + **打开官方下载页** / **重新检测**（诚实边界，不许猜）。

**更新中的界面**：与安装共用同一套进度与状态（下载进度 / 校验 / 安装 / 等权限询问 / 复检），话术换成 **正在更新 Node.js…** / **正在更新 pnpm…**；权限询问与结果态照第 7、8 节。
归属 = 版本管理器且**不需要装版本管理器**时，**没有下载与校验两段**：进度区从「正在让它装 Node.js…」开始（不画进度条、不出现百分比）。

**更新完成必须同时给出三个事实**（需求文档 8.2，t29 补齐档位与实测）：

- **更新前**版本与档位（例：`v26.9.0（当前版）`）；
- **更新后**版本 —— **实测到的那个**（复检那一刻真的跑出来的 `node --version`），不是"我们打算装的那个"；没测到就照实说 **没测到版本**（不许拿目标版本冒充实测值）；
- 结论。原样文案：**Node.js：vX（<档>） → vY（<档>）。** / **pnpm：<旧版本> → <新版本>。**；
  **换档**时结论里必须出现「换档」这个词：**Node.js：v26.9.0（当前版） → v24.21.0（稳定版）—— 换档完成。**；
  **没变化** 时照实说 **版本没有变化（还是 <版本>）**，并把「重新检测」摆在旁边。

**互斥**：更新与安装共用一个"忙"位（2.9）：更新进行中时，装 pnpm / 装 dsh / 另一个更新全部禁用。

## 11. 键盘可达性

### 11.1 通用

- **任何一步都能只用键盘完成**：检查 → 读结论 → 展开确认区 → 开始 → 取消 → 跳过 → 逃生 → 进入界面，全程不需要鼠标。
- **焦点可见**：所有可聚焦元素都走应用既有的焦点样式（视觉规格定），不许 `outline: none` 了事。
- **不用 tooltip 承载必要信息**：所有"为什么"都写在页面里；`title`/tooltip 只做补充。
- **`Enter` 不提交输入框以外的隐含动作**：只有按钮、单选、可展开区吃 `Enter`；文本输入框里的 `Enter` 只做第 0.3 节写的那件事（在确认区里等同「开始」）。
- **`Esc` 按 0.4**：只退、不前进、不杀安装。

### 11.2 门禁层内的 `Tab` 顺序（挡住页）

按阅读顺序：**当前步骤的单选项 → 「安装」→ 「我想自己去官网下载安装」→ 「展开看详情」→ 「重新检测」→ 逃生口**。
放到实际元素上：

1. 两个安装路径的单选（一组，方向键在组内切换，`Tab` 走出组）；
2. 主操作（安装）；
3. 次操作（我想自己去官网下载安装）；
4. 展开详情；
5. 重新检测；
6. **逃生口（最后一个，永远可达）**。

说明：**逃生口排在最后**是因为它在视觉上就在底部，键盘顺序要跟视觉顺序一致；但它**不因为排在后面就不可达** —— `Shift+Tab` 一步就能到，`Tab` 循环会回到它。

**t29 补充（按 §4.1 修订后的控件）**：第一步的 `Tab` 顺序是 **档位两选一（一组）→ 方法区 → 「安装」→ 「我想自己去官网下载安装」→ 「展开看详情」→ 「重新检测」→ 逃生口**。
方法区**有单选时**才在 `Tab` 顺序里（归属已知时它是一行**不可聚焦的事实行**，不进顺序）；档位控件**必须**在确认区展开**之前**就能到达 —— 它现在是"用户要先看见的东西"，不是确认区里的一个补充按钮。

### 11.3 门禁层内的 `Tab` 顺序（检查中 / 放行页）

| 页         | 顺序                                                                                   |
| ---------- | -------------------------------------------------------------------------------------- |
| 检查中     | 逃生口（默认焦点）→ 重新检测（进行中禁用，禁用的元素**不进 Tab 顺序**）                |
| 放行页     | 进入 DSH Console（默认焦点）→ 再看看环境自检                                           |
| 确认区展开 | 焦点**移进确认区**：开始（默认焦点）→ 取消；`Esc` 收起并**把焦点还给触发它的那个按钮** |
| 进度区展开 | 取消下载 / 不再等待 → 展开输出 → （`Esc` 不做事，见 0.4）                              |

### 11.4 引导步骤内的 `Tab` 顺序（每一步一致）

**标题（不可聚焦）→ 单选/事实区 → 主操作 → 次操作（跳过 / 自己下载）→ 展开详情 → 逃生口**。
确认区展开后在其中循环（上面的规则），收起后焦点回到主操作。

### 11.5 焦点管理

- 步骤前进一步时，**焦点移到新步骤的主操作**（不是丢回 body）—— 键盘用户要知道界面往前走了一步；
- 门禁层收起时（放行 / 逃生），**焦点移到一个有意义的地方**：走逃生口时给主内容区，点「进入 DSH Console」时同样给主内容区；
- **用键盘走逃生口的完整路径**（不需要鼠标）：`Tab`（或 `Shift+Tab`）移动到**先进入界面（环境还没准备好，我稍后自己处理）** → `Enter` → 门禁层收起、焦点落在主内容区 → 然后用既有的键位回到向导：`Ctrl+8` 到环境自检页、`Tab` 到 **重新打开环境向导** → `Enter`（按 2.8 第 2 条；控制台页那条横幅在 `Ctrl+1` 上）。**这条路径必须真的能走通**，它正是"逃生口不被门禁自己挡住"的验收方式；
- 「重新检测」返回后，**焦点留在原地**（不要跳到别处，用户还在看同一屏）；
- 横幅上的「继续配置」点了之后，焦点进入门禁层的当前步骤主操作。

### 11.6 不可用的元素

- **禁用**的按钮不进 `Tab` 顺序（原生 `disabled` 即可）；
- 但**"为什么禁用"必须在界面上看得到**（一句说明或 `title`），不能只靠灰掉；
- **逃生口永远不禁用**（2.7）—— 它是唯一一条"必须永远可用"的按钮。

## 13. 明确不写进界面的东西（措辞红线）

按需求文档第 3 节的词表，界面上**不许出现**下列任何一个词（出现即缺陷）：`EnvCheckId`、`EnvFixPlan`、`EnvFixState`、`judgeEnvironment`、`probe`、`fixAction`、`verbatim`、`COMSPEC`、`NVM_SYMLINK`、`SHASUMS256`、`sha256:`、`PATH`。

**替换说法（这份文档通篇在用）**：

| 不许出现           | 界面上说                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 门禁 / blocked     | **运行环境还没准备好**                                                                                                          |
| 逃生口 / escape    | **先进入界面（环境还没准备好，我稍后自己处理）**                                                                                |
| UAC / 提权 / runas | **管理员权限**；**接下来 Windows 会问你一次是否允许安装**                                                                       |
| PATH / 环境变量    | **系统查找路径**（详情里才出现变量名）                                                                                          |
| nvm / NVM_SYMLINK  | **版本管理器（nvm）**（详情里才出现变量名）                                                                                     |
| 校验 / sha256      | **校验安装包完整性**；**校验依据**（详情里可复制）                                                                              |
| 退出码 / msiexec   | **安装程序**；**安装没能完成（编号 N）** —— 先给一句人话                                                                        |
| skip               | **先跳过这一步** + 后果一句                                                                                                     |
| LTS / current      | **最新稳定版** / **最新当前版**（t29：档位控件的两个选项就用这两个词；`LTS` 只在详情里出现）                                    |
| 用「更新」冒充换档 | **换成稳定版** / **换成当前版**；结论里写 **换档完成**（t29：**目标版本低于当前版本时，那个动作分支里不许出现「更新」这个词**） |

技术细节（路径、变量名、完整地址、退出码、校验值）**可以有**，但必须待在**用户点开的「详情 / 命令原文 / 复制」区域**里。
