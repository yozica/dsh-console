# 重启 dsh 之后自动进 Harness（t46）

**现象**：插件页装 / 卸 / 升级任何东西，改的都是 `package.json` 与 `node_modules`，所以黄条会写
「已改到装配层，重启 dsh 后生效」，旁边两个按钮「稍后」与「立即重启 dsh」。点「立即重启 dsh」之后
**只有状态栏上一句「正在重启 dsh…」**：窗口不切、不上锁、没有结束语 —— 用户在底栏最不起眼的位置
看到一句一闪而过的消息，自然会觉得"点了没用"（用户原话：「点击之后没有后续操作，会让用户感觉没有生效」）。

**目标（用户提的）**：点完之后等 dsh 重启就绪，**自动进入 DeepSeek Harness 页**，并明确说出"已生效"。

**摆法预览**：[`docs/plugin-restart-choices.html`](plugin-restart-choices.html)（零 `<script>`、真实尺寸：
左栏 `--rail-w` 188px、顶栏 36px、启动锁卡片同 `#boot-lock`）。

---

## 1. 四项裁决（t46，用户裁定；全选推荐项）

| #   | 待定项                      | 裁定                                                                 | 为什么                                                                                                               |
| --- | --------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 1   | 从点到就绪的那几秒怎么表现  | **1A 停在插件页 + 启动锁**                                           | 复用现有那一层锁（向导结束后的自动启动就是它），用户已经见过；卡片上直接写"就绪后自动打开 DeepSeek Harness"          |
| 2   | 到了 Harness 页之后的反馈   | **2A 状态栏一句 + 页顶一条可关闭的提示**                             | 用户刚做完一件"有后果"的事（装了别人的代码），让他明确看到"它现在真的在里面"                                         |
| 3   | 这条流程给谁用              | **3B 三处共用**（插件页 / 控制台「重启」/ 环境自检「重新启动 dsh」） | 三处是同一件事（"dsh 要重启才生效"），只给一处加，用户下次（更新 Node 之后）还会碰到同样的空档；只有文案不同         |
| 4   | 自动进 Harness 时顺带全屏吗 | **4A 不主动全屏**                                                    | 全屏会藏掉左栏与状态栏（抢屏）；用户刚点完"重启"，多半还想接着看插件列表。启动时那条老路照旧按 `uiFullscreenOnStart` |

**顺带的第四处调用点**：Harness 页自己的「重启为受管实例」（`#btn-ui-managed`）。它本来就调
`restartFlow`，动作与上面三处是同一件事 —— 用户在 Harness 页上，所以"切页"是空操作，但它同样能拿到
这一套锁与到达提示（否则会出现"三个入口都有反馈、就这个没有"的不一致）。文案按语境分开。

## 2. 状态机与判据

### 2.1 顺序：**意图先立，再动手**

```
点按钮
  → beginRestartNav(reason)          # 先立意图：锁只在 phase 变 starting 的那 5 秒窗口内才会上锁
  → restartFlow(api, getDsh)         # 停 → 等端口释放 → 再拉起（外部实例会先问一次）
  → 失败：failRestartNav(原因)        # 黄条说实话，按钮可再点；不上锁、不切页
```

`dshManager.start()` 一 spawn 完就返回（不等健康检查），所以**意图必须在调用之前立**，否则
`phase === 'starting'` 那一段已经过去了，锁永远等不到上锁窗口。

### 2.2 上锁：启动锁的**第三个回合**

启动锁本身仍是**单向状态机**（`idle → waiting → done`，`done` 之后直接返回，见 AGENTS §7.9）：
本轮不把它改成可重入，而是照 `armAfterGate()`（R-32）的样子**显式开一个新回合** `afterRestart`，
同样带 5 秒窗口 —— 窗口内相位没变成 `starting` 就把回合收成 `done`（**没有等待就不上锁**：
例如重启调用立刻失败、或端口被占）。

锁上的文案按回合分开（`index.html` 里那两句静态文案是"启动"语境）：

| 回合           | 标题                 | 说明                       | note                                                              |
| -------------- | -------------------- | -------------------------- | ----------------------------------------------------------------- |
| `startup`      | 正在启动 dsh 服务    | 正在拉起进程并等待健康检查 | 已等待 N 秒 · 就绪后自动打开 DeepSeek Harness 并进入全屏          |
| `afterGate`    | 正在启动 dsh 服务    | 正在拉起进程并等待健康检查 | 同上（它确实会进全屏）                                            |
| `afterRestart` | **正在重新启动 dsh** | 正在拉起进程并等待健康检查 | **已等待 N 秒 · 就绪后自动打开 DeepSeek Harness**（4A：不提全屏） |

### 2.3 就绪判据（纯函数，自检直接钉）

```ts
ready = phase === 'running' && Boolean(dsh.uiUrl);
```

**为什么必须带 `uiUrl`**：只看 `running` 就切过去的话，Harness 页会停在「还没捕获到带令牌的地址」
那一屏 —— 令牌是 dsh 启动时打印的，健康检查通过之后还要再等它出现在输出里。切过去看见 401 说明，
比不切更让人糊涂。

### 2.4 收尾（四种，都是终态，意图当场清掉）

| 情形           | 判据                                                               | 会做什么                                                                |
| -------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 就绪           | 2.3 的判据                                                         | `currentTab = 'ui'`；给 Harness 页留一条到达提示；黄条收回              |
| 起不来         | **见过 `starting` 之后**又落到 `stopped` / `degraded` / `conflict` | 解锁、**不切页**；黄条写「dsh 还没起来（当前状态：…）」                 |
| 被外部接管     | 相位 = `external`                                                  | 解锁、**不切页**（拿不到令牌，切过去只会看到 401 那一屏）               |
| 超时 90 秒     | 与启动锁同一个 `BOOT_LOCK_MAX_MS`                                  | 解锁、**不切页**；黄条同上                                              |
| 用户说"不等了" | 锁上的「不等了，先进入界面」/ 锁期间按 `Esc`                       | **取消这次跳转**（不切页）；黄条写「dsh 已就绪，可以自己去 Harness 页」 |

> 「不等了」是唯一会**取消**跳转的路径：它表达的是"别替我做主"，那就只解除等待，不再抢页面。

**两个"必须先看见"的前置条件**（都是真机上踩出来的，落在 `lib/restart-nav.ts`）：

- **就绪**要先看见旧实例被停过（`leftRunning`，或带令牌地址确实换了）。少了它，立意图那一刻旧实例
  还是 `running` + 带着旧令牌，"就绪"当场成立 —— 页面瞬间切走、锁根本没出现（实测：点完 600ms
  就已经在 Harness 页上，而重启还在后头跑）。
- **起不来**要先看见它 `starting` 过（`sawStarting`）。少了它，重启必然经过的那个 `stopped` 会被
  当成失败 —— dsh 明明起来了，界面上却写「dsh 还没起来（当前状态：运行中）」（实测）。

## 3. 逐字文案

| 位置                            | 文案                                                                                                                                                                               |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 锁标题（afterRestart）          | 正在重新启动 dsh                                                                                                                                                                   |
| 锁说明                          | 正在拉起进程并等待健康检查                                                                                                                                                         |
| 锁 note                         | 已等待 N 秒 · 就绪后自动打开 DeepSeek Harness                                                                                                                                      |
| 锁上的逃生口                    | 不等了，先进入界面                                                                                                                                                                 |
| 状态栏（就绪后）                | 插件已生效，已打开 DeepSeek Harness（控制台：dsh 已重启，已打开 DeepSeek Harness；环境自检：Node 更新已生效，已打开 DeepSeek Harness；受管实例：已接管为受管实例，内嵌界面已可用） |
| Harness 页到达提示（可关闭）    | 刚刚重启过 dsh，装配层的改动已经加载。以后改你自己的 `cordis.patch.yml` 不用重启。                                                                                                 |
| Harness 页到达提示按钮          | 知道了                                                                                                                                                                             |
| 黄条·进行中                     | 正在重启 dsh… ＋ bundle 列表是启动时读的，起来之后这一页会自动切到 DeepSeek Harness。                                                                                              |
| 黄条·起不来 / 超时              | dsh 还没起来（当前状态：&lt;相位词&gt;）                                                                                                                                           |
| 黄条·被外部接管                 | 端口上的 dsh 变成了外部实例，拿不到它的令牌。                                                                                                                                      |
| 黄条·取消（不等了）             | dsh 已就绪，可以自己去 Harness 页。                                                                                                                                                |
| 黄条·失败                       | 重启失败：&lt;原因&gt;                                                                                                                                                             |
| 黄条·成功（若用户又切回插件页） | dsh 已重启，装配层的改动已加载。                                                                                                                                                   |

黄条的按钮：进行中时两颗都禁用（`稍后` / `立即重启 dsh`）；失败 / 超时 / 被接管时「立即重启 dsh」
回到可点；成功 / 取消后黄条本身就是"已完成"，不再给「立即重启」。

## 5. 哪条自检守着 / 真机怎么验

自检（静态，不需要 Electron）：

- 「重启后进 Harness：就绪判据是 running + 有带令牌地址（只看 running 会切到 401 那一屏）」
- 「重启后进 Harness：意图在调用之前立（start 一 spawn 就返回，晚立就错过上锁窗口）」
- 「重启后进 Harness：三个回合的锁文案分开（afterRestart 不提全屏）」
- 「重启后进 Harness：四个调用点都走同一条流程（含 Harness 页自己的「重启为受管实例」）」
- 「重启后进 Harness：黄条四种状态都有（进行中 / 失败 / 未就绪 / 已生效）」

真机（`npx electron .`，独立 `DSH_CONSOLE_USER_DATA`）：

1. 装一个真插件（`docs` 里那份手写 tarball 或 npm 上的小包）→ 黄条出现 → 点「立即重启 dsh」；
2. 看锁出现（标题「正在重新启动 dsh」）、note 不带全屏、就绪后**自动切到 Harness 页**且到达提示在；
3. 岔路：`Esc`（应留在插件页、不切页）、端口被占（应先报失败、不上锁）、外部实例（应不切页）。
