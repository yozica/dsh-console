插件装完之后怎么"看得见生效"

现在：插件页装 / 卸 / 升级任何东西，改的都是 package.json 与 node_modules，所以黄条会写「已改到装配层，重启 dsh 后生效」，旁边两个按钮 「稍后」与「立即重启 dsh」。点「立即重启 dsh」之后，**只有状态栏上一句「正在重启 dsh…」**， 界面不切、不改样、也没有结束语 —— 用户自然觉得"点了没用"。

你要的行为：点完之后等 dsh 重启就绪，自动进入 DeepSeek Harness 页。 下面是这条流程的几个待定项，各自把能看的摆法摆出来 —— 每一屏都是真实尺寸 （左栏 --rail-w 188px、顶栏 36px、启动锁卡片同 #boot-lock）， 用的也是应用里那套 CSS 变量。

0. 现状点完就没了

点「立即重启 dsh」后：api.restart()（停 → 等端口释放 → 再拉起，最长 10 秒）→ pendingRestart = false（黄条消失）→ 状态栏一句「正在重启 dsh…」。窗口不上锁、不切页。

2. 到了 Harness 页之后给什么反馈选一个

"自动切过去"本身已经是反馈了；这一条是问要不要再说一句"你刚才那个插件已经加载进来了"。

A. 状态栏一句 + 页顶一条可关闭的提示（推荐） 状态栏：「插件已生效，已打开 DeepSeek Harness」；Harness 页顶一条浅色提示 「刚刚重启过 dsh，装配层的改动已加载」+ 一个「知道了」。理由：用户刚做完一件 "有后果"的事（装了别人的代码），让他明确看到"它现在真的在里面"。

3. 这套流程给谁用选一个

现在"重启 dsh"有三个入口，各自写完就完了：插件页「立即重启 dsh」（api.restart()）、 控制台页「重启」（走 restartFlow，外部实例会先问一次）、 环境自检详情页「重新启动 dsh」（更新 Node 之后，走 api.start()）。

A. 只改插件页那颗按钮 范围最小、只解决你提的这一处；另外两处保持现状（各自那句话照旧）。
B. 三处共用同一条流程（推荐） 把"重启 → 等就绪 → 自动进 Harness → 说一句"抽成一个共享动作（放 lib/dsh-actions.ts 或新开一个小模块），三处都调它。理由：三处是同一件事 （"dsh 要重启才生效"），只给一处加，用户在下一次（更新 Node 之后）还会碰到同样的空档。 差别只在文案：插件页说"装配层改动已加载"，环境自检说"Node 更新已生效"，控制台说"dsh 已重启"。

4. 自动进 Harness 时要不要顺带进全屏选一个

应用启动时那条老路（设置项 openUiOnStart + uiFullscreenOnStart）会 "就绪后切到 Harness 并进全屏"。这条新流程要不要跟它一致？

A. 不主动全屏（推荐） 只切页。全屏是一件抢屏的事（左栏、状态栏、页面工具条都会被藏起来），用户刚才只是在 插件页点了个"重启"，多半还想接着看插件列表 / 装下一个；此时把界面变成全屏会让人找不着北。 启动锁那句提示也要跟着改成「就绪后自动打开 DeepSeek Harness」（现在写的是"并进入全屏"）。
B. 跟设置走：uiFullscreenOnStart 开着就顺带全屏 与"启动时自动打开"完全一致，喜欢全屏工作的人少点一次。但这与设置项的语义有偏差 —— 它的名字是"启动时"（on start），这里不是启动。

5. 没成功的时候我按默认做，你可以改

这几条不摆选项了（都是"别骗用户"的默认做法），只是先告诉你我会怎么写 —— 有意见直接说。

  • 重启调用失败（api.restart() 报错）：不上锁、不切页，黄条变红 「重启失败：<原因>」，按钮还能再点一次。
  • 等了 90 秒还没就绪（与启动锁同一个上限）：解锁、不切页，黄条写「dsh 还没起来 （当前状态：…）」，并把「立即重启 dsh」换回可点状态。
  • 期间 dsh 被外部实例接管（phase === 'external'）：解锁、不切页 —— 外部实例拿不到令牌，切过去只会看到"401 / 需要重启为受管实例"那一屏，等于更糊涂。
  • 用户自己按了 Esc（锁上的"不等了，先进入界面"）：解锁、留在插件页， 黄条保留一句「dsh 已就绪，可以自己去 Harness 页」。
