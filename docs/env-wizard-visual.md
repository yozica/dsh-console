**两个必须先说清的前提**：

1. 这一屏是**应用自己的骨架**，不是一张浮在应用上的对话框。门禁层出现时，左栏与状态栏被盖住，而门禁层在**同样的位置**给出自己的左轨与底条 —— 用户看到的不是"弹窗"，是"这台应用把中段换成了向导"（§2 展开）。
2. 这一屏上**没有"装饰"，只有"事实"**：出现的每个版本号、路径、主机名、百分比都来自主进程的报告或计划；界面不自己拼、不自己算、不假装进度（交互 §7.5、需求 §3.1 第 3 条）。

## 1. 设计计划（`frontend-design`）与它落到哪些决定上

### 1.1 三问

| 问         | 答                                                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 这是什么屏 | 一台**什么都没装的 Windows 11** 上，用户第一次打开 DSH Console 时看到的第一屏。它要拦住主界面，直到这台机器的运行环境够用        |
| 谁在看     | 一个不知道 Node / npm / pnpm / dsh 分别是什么的人；他此刻的情绪是"我点开了它，它不让我进去"，而且**他不能确定这是不是坏了**      |
| 这一屏的活 | ① 让不知所措的人知道**下一步只做什么**；② 在**失败与等待**的时候仍然显得可靠、可信（这一屏最可能被人截图去问别人"这是正常的吗"） |

### 1.2 设计计划的四件套

**配色：不动既有色板。** 四级表面（页底 `--bg` / 面板 `--surface` / 抬升 `--surface-2` / 下沉井 `--well`）加一层 `--rail`，半透明发丝线两条，一个交互强调色（青），四个状态语义色（run / amber / rose / sky）。本文唯一的颜色层动作是**修订浅色主题下四个状态色的取值**（§9.2 附实测对比度），因为实测发现它们压在浅色底上不足以承载小字 —— 那是"取值不够"，不是"缺少颜色"。

**字体：不动。** 界面 `--sans`（IBM Plex Sans + 中文回退）、机器字节 `--mono`（IBM Plex Mono）。门禁层不额外声明字体族，中文落在回退链上（§8）。

**构图：把应用自己的骨架换掉中段。** 左轨宽度直接取 `--rail-w`（188px），底条内边距直接取状态栏的（左右 20px），内容列从 208px 起 —— 与九页内容的左边距**同一个值**。门禁层收起时，左栏与页面回到原位，屏幕上没有任何东西横向移动。

**五个原则（这一屏的判据）**：

1. **一屏只有一件事可做**：队列只以左轨上的节点存在；正文里只有"当前步骤"这一块是可操作的，后续步骤不可展开（交互 §2.4 第 5 条）。
2. **骨架不因为状态变化而移动**：检查中 / 挡住页 / 放行页共用同一个左轨、同一条底条、同一个左边距；失败、等待、未确定**都在原地发生**，不弹窗、不跳页、不换屏。
3. **颜色是第二信号**：第一信号是形状（实心 / 空心 / 虚线 / 呼吸 / 尺寸）与**状态词文字**。任何状态都不允许只靠颜色区分（这条同时解决色盲与两套主题）。
4. **面子给"事实"，不给"我们"**：不解释我们是多聪明，只把命令原文、下载来源、装到哪、要不要管理员权限、复检结论摆出来。
5. **三个"唯一"**：整屏只有**一处阴影**（当前步骤卡）、只有**一处实底强调色**（本步唯一的主按钮）、只有**一次编排的动效**（第一份报告回来时左轨节点落点 + 脊线走完）。

### 1.3 对照"通用默认"做一次自我批评

`frontend-design` 点名了当下生成式设计最容易落进去的几套默认观感。逐条核对本文：

| 默认观感                                                                                 | 本文                                                                                                                                                                                                                               |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 暖米底 + 高对比衬线 + 陶土橙强调色                                                       | 无关：色板是既有产品的身份，本文不引入任何新色相                                                                                                                                                                                   |
| 近黑底 + 单一酸性亮色                                                                    | **这是本产品的既有长相**（控制台底色 + 青），不是本文的选择；本文没有新增第二个亮色                                                                                                                                                |
| 报章式布局：零圆角 + 密集竖栏 + 满屏发丝线                                               | 明确拒绝：圆角分级 14 / 10 / 8 / 999，行宽只有 620px，页面留白充足                                                                                                                                                                 |
| **SaaS 卡片套件：内容切成一堆同款圆角卡 + 每张卡同一个柔和阴影**                         | **这是本文最主要要避开的默认**。做法是**禁止给非当前元素做卡**：门禁层只有一张卡（当前步骤）；后续步骤是轨道上的节点，不是卡；确认区是下沉井不是卡；提示是软底色条不是卡；只有一处阴影                                             |
| 模板化装饰：全大写 eyebrow、`A · B · C` 式元信息串、小数据用等宽、链接与按钮尾部追加 `→` | 本文不用 eyebrow 标签；不用 `·` 拼元信息（唯一的 `·` 沿用既有状态栏）；等宽只给机器输出的字节（命令 / 路径 / 主机名 / 版本 / 校验值）；`→` **只**出现在版本前后对照（那是一次真实的变化，且文案由交互 §10.5 钉住），不追加在按钮上 |

**"照抄现有页面配色算不算没设计"的反问**：配色本来就是这套产品的身份（AGENTS §7.12 记着它按这个技能走过两轮），在一屏已经成型的应用里另起一套色相才是失职。所以本文把原创性的预算全部花在三件事上：**构图**（应用自己的骨架换掉中段）、**队列的表达**（左轨 + 脊线 + 五个状态词，而不是一排灰卡）、**状态的可信度**（失败不换地方、进度不装、颜色不做唯一信号）。

**换成"居中卡片 + 一个大按钮"会失去什么**（三条，都对着这一屏的活）：

1. 用户读不完那份计划（620px 行宽与左对齐的文档式排布是为了"读完"，居中 460px 卡片会把"将要执行"挤成小字注脚）；
2. 用户不知道**后面还有几步**（居中卡片没有位置放队列，只能加一行灰字"还有 2 步"，那是说明不是结构）；
3. 失败时用户得重新找地方看结论（居中卡片一旦收起或换成另一张卡，视线要重新定位；本文坚持结果行与事实行是**同一个槽位**）。

## 2. 一句话构图：门禁层 = 应用自己那副骨架，换掉中段

```
应用正常的样子                         门禁层显示时的样子
┌───────┬──────────────────────┐        ┌───────┬──────────────────────────────┐
│ 左栏  │ 顶栏（36px，可拖动） │        │ 顶栏：运行环境准备（36px，可拖动）          │
│ 188px │──────────────────────│        │───────┬──────────────────────────────│
│ 导航  │ 页面内容（20px 内边距）│        │ 左轨  │ 内容列（20px 内边距，620/760px）│
│ 状态块│                      │        │ 三步  │ 标题 / 当前步骤卡 / 提醒行      │
│       │                      │        │ +脊线 │                              │
│ 主题  │                      │        │       │                              │
├───────┴──────────────────────┤        ├───────┴──────────────────────────────┤
│ 状态栏（--rail，左右 20px）  │        │ 底条（--rail，左右 20px）：逃生口       │
└──────────────────────────────┘        └──────────────────────────────────────┘
```

**为什么这样构图**（对着 §1.1 的两件活）：

1. **要读完一份计划**：左对齐的文档式排布 + 620px 行宽，比一张居中卡片更能让人从头读到尾；"将要执行"能有两列事实表的位置。
2. **一屏只有一件事可做**：队列不需要挤进正文，它就在左轨上；正文里只有当前步骤这一块是被"翻开"的。
3. **失败与等待时不换地方**：骨架由左轨（`--rail`）+ 内容列（`--bg`）+ 底条（`--rail`）三块组成，这三块在任何状态下都不变位置，变的只是内容列里的字与左轨上的灯。

**为什么不做成居中卡片 / 蒙层 / 左栏第 10 页**：交互 §2.1 已经定了方向（覆盖层、不做页面、顶栏不挡）；本文补上视觉理由 —— 居中卡片适合"说一句话就结束"（既有的启动锁与关窗确认正是这种），而门禁要让用户读完一份计划、做三次决定、并且**能一直看到自己走到哪一步**，那是文档 + 轨道，不是卡片 + 按钮。

## 3. 骨架与尺寸

### 3.1 三块与它们的盒

| 块         | 位置与尺寸                                                                        | 变量 / 依据                                                 |
| ---------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 门禁覆盖层 | `top: 36px`（顶栏之下）、左右下贴边；层号低于启动锁（见 §9.1 的 `--z-gate`）      | 顶栏高度 = `--bar-h`（36，与 `TITLEBAR_HEIGHT` 一致）       |
| 左轨       | 宽 188px；占满覆盖层高度；右侧一条发丝线；内边距 16 / 12 / 12                     | `--rail-w`、`--rail`、`--hairline`（与既有左栏逐项相同）    |
| 内容列     | 从左轨右缘起；左右内边距 20px，上 24px，下 20px；最大宽 760px；正文块最大宽 620px | `--wizard-card`、`--wizard-read`（新增，见 §9.1）           |
| 底条       | 贴在覆盖层底部；左右内边距 20px，上下 10px；上缘一条发丝线；内容左对齐            | 与既有状态栏同一处（左右 20px、`--rail`、上缘发丝线）       |
| 提示条     | 在内容列里、当前步骤卡之下；不贴边、不浮起                                        | `--amber-soft` + `--r-panel`（沿用既有横幅的做法，见 §5.8） |

**20px 是既有约定，不是新数值**：`.pane` 本身没有任何内边距，页面级内边距由各页自己给（AGENTS §7.14）—— 门禁层不是页面，所以这份内边距由它自己承担，但**数值与页面一致**（左右 20px），这样门禁层的标题与页面标题在同一条竖线上。

### 3.2 内容的纵向节奏

| 间距                     | 值      | 用在哪                                                              |
| ------------------------ | ------- | ------------------------------------------------------------------- |
| 标题 → 副标题            | 6px     | 与既有 `.close-title` → `.close-lead`、`.boot-title` 同量级         |
| 副标题 → 卡片            | 20px    | 段落与"块"之间的呼吸                                                |
| 卡内：标题 → 为什么      | 4px     | 一句话紧跟着标题                                                    |
| 为什么 → 事实行          | 12px    | 事实行是可以细读的下一层                                            |
| 事实行 → 展开详情        | 8px     | 同一条事实的补充                                                    |
| 事实行 → 选择区 / 操作行 | 16px    | 块之间的标准间距（与既有 `.focus-card` 的 `margin-top: 16px` 一致） |
| 选择项之间               | 8px     | 单选卡之间                                                          |
| 操作行内部               | 8px     | 与既有 `.btn-row` 一致                                              |
| 卡内边距                 | 18 / 20 | 与既有 `.focus-card` 一致（18px 18px 20px 20px）                    |
| 左轨节点之间             | 18px    | 节点 + 两行字的高度由内容决定，间距固定                             |

### 3.3 层级只用圆角与阴影（四级表面在门禁层的分配）

| 层     | 变量                               | 门禁层里是谁                                                                 | 圆角                                                | 阴影                             |
| ------ | ---------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------- |
| 页底   | `--bg`                             | 覆盖层的底、内容列的底                                                       | —                                                   | 无                               |
| 框架   | `--rail`                           | **左轨**与**底条**（与应用自己的左栏 / 状态栏同一个变量、同一个位置）        | 无（整块贴边）                                      | 无                               |
| 面板   | `--surface`                        | **当前步骤卡**（整屏唯一一张卡）；输出区（沿用既有形态）                     | `--r-card` 14px                                     | `--shadow-focus`（整屏唯一一处） |
| 抬升   | `--surface-2`                      | 卡内的**选择项**、命令原文小砖、结果行里的"读数"                             | `--r-panel` 10px（大块）/ `--r-control` 8px（小砖） | 无                               |
| 下沉井 | `--well`                           | **确认区**、流式输出正文、进度条轨道                                         | `--r-panel` 10px / 999px（轨道）                    | 无                               |
| 发丝线 | `--hairline` / `--hairline-strong` | 左轨右缘、底条上缘、卡内分隔、选择项未选中边框、命令小砖边框、进度条轨道边框 | —                                                   | —                                |

**三条硬规则**：

- **同一层级的元素用同一个圆角**：卡 = 14、内嵌面板 = 10、控件 = 8、状态 pill 与进度轨道 = 全圆。
- **阴影不给层级"再加一层"**：抬升的表面（选择项、小砖）靠 `--surface-2` 与发丝线表达，绝不加阴影（否则就回到"每张卡片同款阴影"）。
- **发丝线全部半透明**：两套主题下都用 `--hairline` / `--hairline-strong`，不用实心灰（浅色下实心灰会变成"分区"，深色下会变成"描边"）。

## 4. 左轨：队列的唯一住所

### 4.1 结构

```
左轨（188px，--rail）
┌──────────────────┐
│ DSH Console      │  ← 沿用既有左栏的品牌块（--t-lg 600 + 一行 --t-sm 的副标题）
│ 运行环境准备     │     副标题写门禁层的状态，不写"门禁"两个字
│ ──────────────── │  ← 发丝线（与既有左栏 `.rail-foot` 同款分隔）
│                  │
│ ●  第一步        │  ← 节点（8px 灯）+ 标题（--t-md，当前步骤 600 / 其余 400）
│ │  安装 Node.js  │
│ │  进行中        │  ← 状态词（--t-xs，第二信号；颜色是第一信号之外的补充）
│ │                │
│ ○  第二步        │
│ │  安装 pnpm     │
│ │  等上一步完成  │
│ │                │
│ ○  第三步        │
│    安装 dsh      │
│    等上一步完成  │
└──────────────────┘
```

### 4.2 节点与脊线

| 元素     | 规格                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| 节点     | 圆形灯：非当前 8px；当前 11px（既有 `.lamp` / `.lamp-lg` 两档）。节点居中在一个 14px 宽的列里    |
| 脊线     | 2px 宽的竖线，位置 = 节点列的中线（与节点共用同一个来源：`--wizard-rail-dot`），画在节点**后面** |
| 脊线着色 | **已经走完的那一段**用 `--run`（表示"这一步已成"），剩下的一段用 `--hairline-strong`             |
| 节点形态 | 见 §6.1 的五态表（实心 / 实心+晕 / 空心 / 虚线空心 / 呼吸）                                      |
| 文字     | 标题两行以内不折行；状态词单行；`Tab` 顺序里**没有**轨道节点（它们不可聚焦、不可点，纯读数）     |
| 尺寸     | 节点列 14px + 间隙 8px + 文字列；左轨内边距 16 / 12 / 12（与既有左栏一致）                       |

### 4.3 五个状态词与"没轮到的步骤不刷红"

状态词沿用交互规格的五个词，逐字照用：**已完成 / 进行中 / 待办 / 已跳过 / 没测出来**。

节点颜色规则（一条容易被忽略、但决定这一屏情绪好坏的规则）：

| 情形                                 | 节点                                     | 理由                                                                                                                                     |
| ------------------------------------ | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 已完成                               | `--run` 实心 + 3px 晕；脊线该段着色      | 事实是绿的，无论它是不是当前步骤                                                                                                         |
| 已跳过                               | 空心环 + 中性墨（`--ink-dim`）           | 跳过是**用户的决定**，不是故障，不许借 amber / rose                                                                                      |
| 没测出来                             | **虚线**空心环 + `--ink-faint`           | "我们的探测失灵"不是用户的隐患，不许借 amber                                                                                             |
| 需要注意                             | 空心环 + `--amber`（1.5px 描边、无填充） | 与既有环境自检页的 warn 灯同款（空心 = 还没到不能用的地步）                                                                              |
| 当前步骤，判定为待办                 | 11px `--rose` 实心 + 3px 晕              | 它才是"现在要处理的事"                                                                                                                   |
| 当前步骤，正在执行                   | 11px `--sky` 实心 + 3px 晕 + **呼吸**    | 呼吸是"在动"的唯一表达（既有的 `breathe` 关键帧，无新增动效）                                                                            |
| **还没轮到、判定同为「待办」的步骤** | **8px 空心环 + `--ink-faint`**           | **不刷红**：这台机器什么都没装是事实，但把三步全刷成红色等于告诉用户"电脑坏透了"；按顺序做完每一步都会变绿，红灯留给"现在要处理的那一步" |

放行页（§5.7）上三个节点全是 `--run` 实心、脊线整条走完 —— 那是这一屏唯一一次"整条轨道成立"的画面。

## 5. 逐屏结构与关键尺寸

先定四个**跨屏复用件**，后面每一屏只说"用哪个件、里面写什么"。

### 5.0 四个复用件

**A. 事实行（fact row）** —— 沿既有环境自检页那一行的解剖，让两屏看起来明显是同一个程序。

```
● 外部 Node    这台电脑上没有找到 Node                          [展开看详情]
│  │            └ 结论原文（--t-sm，--ink-dim，行高 1.7，任意处可断行，可选中）
│  └ 结论词（--t-xs，状态色——浅色主题下的取值见 §9.2）
└ 8px 灯（§6.1 五态）
```

| 项     | 规格                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------- |
| 布局   | `灯 / 结论词（一行，与详情基线对齐） / … / 右侧次操作`；灯与文字顶对齐（既有 `.env-row` 的做法）              |
| 文字   | 结论词 `--t-xs`；结论原文 `--t-sm`、`--ink-dim`、行高 1.7                                                     |
| 展开   | 「展开看详情」是 `--t-xs` 的 ghost 小按钮（可聚焦、`Enter` 可开、`Esc` 可关，交互 §0.4）                      |
| 详情区 | 展开后是**行内**的一块（不是 tooltip），下沉井 + 等宽，逐条列出该步骤用到的自检项原文（路径、变量名可以出现） |

**B. 命令块（command block）** —— 完全沿用既有环境自检页的写法：等宽、下沉井底、发丝线边、`--code-ink` 文字，右侧一颗「复制」小按钮。命令原文可折行、**不许省略号截断**。

**C. 提示块（notice）** 分两级，两级**都不许做成卡片**（不许有阴影、不许有自己的圆角样式旋钮）：

| 级别       | 什么时候用                                                                                      | 形态                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 提醒（软） | 未校验完整性 / 安装包没有数字签名 / 会停掉正在跑的 dsh / 内网连不上 / 有别的程序在用这个 Node   | `--amber-soft` 底、圆角 `--r-panel`、内边距 11 / 14、`--t-sm`、行高 1.7，开头一句用 `--ink` 加粗；同既有横幅            |
| 决策       | 需要用户**明确选一次**（未签名继续 / 未校验继续 / 更新完要不要重启 dsh / 跳过 pnpm 的二次确认） | 下沉井底 + 左边 3px `--accent` 条 + 圆角 `--r-panel` + 内边距 11 / 13（与既有确认区同款）；**内部不出现主按钮**（§6.3） |

**D. 结果行（result row）** —— 成功 / 失败 / 未确定**共用同一个槽位**，这是"失败时也可信"的关键：结论永远出现在事实行的正下方，不弹窗、不跳页、不换屏。

```
● 结论句（一个字都不省的事实）            ← 灯 = 状态色；句 = --t-lg 600 --ink，行高 1.25
  一句话说明（复检结论 / 下一步该干什么）    ← --t-sm --ink-dim 行高 1.7
  [出路 1] [出路 2] [出路 3]                ← btn-row，全部是可点的普通按钮
```

| 结果的类别             | 灯                       | 结论句的语气                                                       | 按钮行                                           |
| ---------------------- | ------------------------ | ------------------------------------------------------------------ | ------------------------------------------------ |
| 成功                   | `--run` 实心 + 晕        | 陈述已发生的事实（"Node.js vX.Y.Z 装好了，…"）                     | 1 个主操作（前进到下一步，或"再看看环境自检"）   |
| 失败 / 什么都没改      | `--rose` 实心 + 晕       | 先给一句归纳过的人话，再给原文尾部；"什么都没改"只在复检支撑时才说 | 2~3 个出路，**第一个出路不一定是主按钮**（§6.3） |
| 未确定（我们不再等待） | **空心环 + `--ink-dim`** | 只说事实（"安装可能还在后台进行"），不给成功也不给失败             | 「重新检测」+「打开官方下载页」                  |

### 5.6 结果与失败态

> 交互依据：交互 §7.6 的各结果态、§8 的管理员权限三种结果。**视觉上只有三类**（§5.0 D），各结果态只是文案不同。

| 类别                      | 灯与色                                               | 结论句之后                                  | 按钮行（按交互给的顺序，从左到右）                                                      |
| ------------------------- | ---------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------- |
| 成功（装好了 / 已经最新） | `--run` 实心 + 晕                                    | 复检结论 + "其它终端要重开一次"（步骤 1）   | 1 个主操作（进入下一步 / 进入界面）                                                     |
| 什么都没改（拒绝 / 取消） | `--rose` 实心 + 晕                                   | 一句人话 + 原文尾部（认不出就只给原文尾部） | 「改用不用管理员权限的方式安装」（拒绝时）/「重新检测」/「再试一次」/「打开官方下载页」 |
| 校验没通过 / 未校验       | `--rose` / `--amber`                                 | 事实 + 出路                                 | 「换一个下载源再试」/「仍然继续」/「打开官方下载页」/「重新检测」                       |
| 网络不通 / 内网           | `--rose`（网络） / `--amber`（连不上外网的事实说明） | 三类归纳之一 + 三条出路                     | 「用浏览器打开下载页」/「换一个下载源」/「重新检测」                                    |
| 装完仍找不到 / 跑不动     | `--amber`                                            | 事实 + 两条出路                             | 「重新检测」/「重开一次应用」/「换一个 Node」/「打开官方下载页」                        |
| 未确定（不再等待）        | **空心环 + `--ink-dim`**                             | 只陈述事实                                  | 「重新检测」/「打开官方下载页」/「我确认安装已经结束」（最后一个来自冻结 R-06）         |

**三条不许违反的视觉纪律**：

1. **失败不换地方、不弹窗、不带红色整屏**：结果行出现在事实行正下方；卡片仍在原位；左轨的节点**不因为失败变成红色**（失败不是"这台电脑不可用"，是"这次没成"）。
2. **"什么都没改"这句话旁边必须有复检的事实**：它出现的前提是复检结论为"仍缺"，界面上把结论原文一起摆出来（交互 §8.1 的硬要求：这句话本身是一次探测的产物）。
3. **未标定的结果不许上色**：我们不知道的事情（"安装可能还在后台进行"）一律用中性（空心环 + `--ink-dim`），不许用绿也不许用红 —— 颜色在这三块里代表"我们确定的事实"。

## 6. 状态语义色与交互强调色：逐条定死

### 6.1 四个状态语义色 + 两个"不是状态"的状态

| 状态               | 变量                                 | **第一信号：形状**                             | 第二信号：色相 | 出现的地方                                                                         | 不许用来表达                                                                      |
| ------------------ | ------------------------------------ | ---------------------------------------------- | -------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 正常 / 已完成      | `--run`                              | 8px 实心圆 + 3px `--run-soft` 晕；脊线该段着色 | 绿             | 左轨节点、事实行、结果行、放行页三行、脊线                                         | 不许用来表示"我们的动作在跑"（那是进行中）                                        |
| 需要注意           | `--amber`                            | **空心环**（1.5px 描边、无填充、无晕）         | 琥珀           | 左轨的 warn 节点、提醒块、常驻横幅、未校验 / 未签名 / 内网 / 别的程序在用这个 Node | 不许用来表示"进行中"（会与"在等"混）                                              |
| 不可用             | `--rose`                             | 8px 实心圆 + 3px `--rose-soft` 晕              | 玫红           | 事实行（缺东西）、结果行的失败结论句                                               | 不许用在按钮上表示"危险"（那是既有 `.btn.danger` 的语义，门禁层里没有破坏性操作） |
| 进行中             | `--sky`                              | 8px 实心圆 + **呼吸** + 晕；6px 进度条填充     | 青蓝           | 左轨节点、状态行、进度条填充                                                       | **不许静止地单独使用**（必须同时有"在动"或百分比文字，见 §6.5）                   |
| 已跳过（非状态）   | 无（`--ink-dim` + 空心环）           | 空心环                                         | 只有墨         | 左轨节点、自检页那一行、「已跳过」pill                                             | 不许借 `--amber` / `--rose`（跳过是用户的决定，不是隐患也不是故障）               |
| 测不出来（非状态） | 无（`--ink-faint` + **虚线**空心环） | 虚线空心环                                     | 只有墨         | 左轨节点、没测全横幅的引用位置                                                     | 不许借 `--amber`（"我们的探测失灵"不是用户的隐患）                                |

**为什么把两个"不是状态"的态单列**：交互规格要的五个状态词里，只有三个是**这台电脑的事实**，另两个是**我们或用户的状态**。把它们混进状态色，等于把"用户自己的决定"和"我们的失灵"都染成警告色 —— 这一屏最忌讳的就是让用户替我们的问题负责。

### 6.2 交互强调色（`--accent`）的四条用法

| #   | 用法                    | 具体形态                                                                          |
| --- | ----------------------- | --------------------------------------------------------------------------------- |
| 1   | 本步唯一的主操作        | `btn primary` 实底 + `--accent-ink` 文字（**一屏最多一处实底**，见 §6.3）         |
| 2   | 键盘焦点                | 既有 `:focus-visible`（2px `--focus` 环 + 2px 偏移），不新增焦点样式              |
| 3   | 选中                    | 选择区的选中项：`--accent-soft` 底 + 1px `--accent` 边；单选圆点用 `accent-color` |
| 4   | **决策块**的左边 3px 条 | 确认区 / 需要用户明确选一次的块（§5.0 C 的"决策"级）                              |

**四条不许**：不许用强调色表示任何**状态**（状态是这台电脑的事实，强调色是"你来点"）；不许给卡片描边；不许用在图标上做装饰；不许在同一屏出现两处实底（进行中的屏幕上主操作已让位给中性的「取消 / 不再等待」，所以那一屏**没有**强调色实底 —— 这也顺手避免了"进行中的青蓝进度条"和"青蓝按钮"挨在一起比色）。

### 6.3 主按钮清点（逐屏）

| 屏                           | 强调色实底 | 是什么                                                                 |
| ---------------------------- | ---------- | ---------------------------------------------------------------------- |
| 检查中                       | 0          | 逃生口是中性按钮（它不是 CTA）                                         |
| 挡住页                       | 1          | 当前步骤卡里的主操作「安装」                                           |
| 确认区展开                   | 1          | 「开始」（此时卡里的主操作被收起区域取代，数量仍是 1）                 |
| 进行中（下载 / 安装 / 复检） | **0**      | 只有中性的「取消下载」/「不再等待」                                    |
| 结果（成功 / 失败 / 未确定） | 0 或 1     | 成功时给下一个主操作；失败与未确定时**一个都不给**（出路都是普通按钮） |
| 放行页                       | 1          | 「进入 DSH Console」                                                   |
| 更新确认区                   | 1          | 「开始」                                                               |

**需要用户明确确认的场合不出现主按钮**（未签名继续 / 未校验继续 / "跳过 pnpm"的二次确认）：所有选项都是同一视觉等级的普通按钮，且**安全的那个在左**（「换一个下载源再试」在「仍然继续」之前）。理由：主按钮的位置在这套界面里意味着"回车就这么办"，而我们恰恰不希望用户在没读懂的情况下默认继续。

### 6.4 禁用态与读数态

门禁层与自检页的按钮有**三种**"不能点"，视觉上必须分得开：

| 种类                     | 例子                       | 形态                                                                                        |
| ------------------------ | -------------------------- | ------------------------------------------------------------------------------------------- |
| 忙碌（临时不可用）       | 安装动作在跑时其它动作按钮 | 既有禁用形态（降透明度）+ `title` 写明原因：**正在执行上一步的操作，完成后按钮会自动恢复**  |
| 不可用（条件不满足）     | 检查中的「重新检测」       | 同上，并**不许**用"点了之后弹一句已经在跑"来代替按钮态（交互 §2.9）                         |
| **读数**（本来就没动作） | 「已经是最新版（vX.Y.Z）」 | `--surface-2` + `--hairline` + `--ink-faint` 文字，**不降透明度**：它是信息，不是坏掉的按钮 |

**读数态为什么必须单独一支**：需求 §8.2 要求"已经是最新"不许是一个点了什么都不发生的按钮，但交互 §10.2 又要求它占着同一个槽位。视觉上的答案就是：形状还是那个槽位（同一高度、同一圆角），但**没有主色、没有边框强调、不褪成灰色**，读起来像一行读数。

## 7. 动效、焦点与交互反馈

### 7.1 一次编排的动效（这一屏唯一一次"非用户触发"的动）

**触发**：第一份报告回来，门禁从"检查中"进入"挡住页"（或放行页）的那一刻。

**做什么**（按顺序，总时长 `--dur-screen` ≈ 220ms）：

1. 左轨的脊线从品牌块下沿向下"长"到第一个节点；
2. 三个节点按顺序落点（每个错开 40ms）：先是最上面那个；
3. 每个节点落点后，它的状态词在 80ms 内淡入；
4. 内容列里"检查中"的标题与缺口环换成"运行环境还没准备好"的标题与副标题（**同位置替换，不做位移**）。

**为什么只做这一次**：这一屏最需要"被相信"的时刻就是"我们读完了你的机器、这是结论"；其余任何进入、悬停、切换都不做动画（`frontend-design`：一次编排胜过满地撒花）。**放行页**复用同一段动效的最后一步：最后一段脊线走完着色，其余不动。

### 7.2 其余允许出现的"动"（全部是既有做法）

| 场景              | 动在哪                                   | 时长             |
| ----------------- | ---------------------------------------- | ---------------- |
| 进行中的状态灯    | 既有的 `breathe` 呼吸（8px 点）          | 1.2s 循环        |
| 下载进度          | 进度条宽度过渡                           | `--dur`（140ms） |
| 检查中的缺口环    | 匀速旋转                                 | 900ms 循环       |
| 控件的悬停 / 按下 | 只改边框与文字色（既有 `.btn` 的做法）   | `--dur`          |
| 按钮忙碌          | 既有 `aria-busy` 的图标自转 + 0.7 透明度 | 900ms 循环       |

**明确不做**：整块内容的淡入淡出（除了 §7.1 那一次）、卡片的悬停位移或缩放、每张卡的入场动画、进度条的"流光"效果、"正在校验"的假进度动画、任何无限循环的装饰动效。

### 7.3 减弱动效

既有的 `prefers-reduced-motion` 分支必须覆盖新增部分：**§7.1 的编排动效整体取消**（直接呈现最终状态，节点与脊线一次到位）、呼吸与自转取消。进度条宽度过渡保留（它是"值变了"，不是装饰）。

### 7.4 焦点（视觉部分）

`Tab` 顺序、焦点管理与"用键盘走通逃生口"的路径由交互 §11 定死，本节只补视觉：

| 项         | 规格                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 焦点环     | 既有 `:focus-visible`（2px `--focus` + 2px 偏移）；卡片、选择项、底条按钮上的环都必须清晰（`--focus` 为强调色 45% / 35% 透明度） |
| 默认焦点   | 检查中 = 逃生口；挡住页 = 主操作「安装」；确认区展开 = 「开始」；放行页 = 「进入 DSH Console」；步骤前进一步 = 新步骤的主操作    |
| 不可聚焦   | 左轨的节点与状态词、事实行的文字、提示块、进度条、状态行                                                                         |
| 焦点可见性 | 禁止 `outline: none`；底条贴在窗口下缘，焦点环仍需完整可见（按钮距底边 ≥ 10px，环不会出界）                                      |
| 焦点不跳   | 「重新检测」返回后焦点留在原地；收起确认区后焦点回到触发它的按钮（交互 §11.5）                                                   |

### 7.5 悬停与按下

- 可点元素悬停：只改边框（`--hairline-strong` → `--ink-faint`）与文字色（`--ink-dim` → `--ink`）；主按钮悬停用既有 `filter: brightness(1.1)`。
- 选择项悬停：只改边框，不改底、不加阴影（否则会有两张"选中"的卡）。
- 按下：不位移、不缩放。
- 鼠标指针：按钮 `pointer`；忙碌状态 `progress`（既有做法）。

## 8. 中文排版与既有排版约定

### 8.1 字体：不新增，中文走回退

- 门禁层**不声明** `font-family`：界面文字继承 `--sans`，机器字节继承 `--mono`。
- `--sans` 的链是 `'IBM Plex Sans' → 'Segoe UI Variable Text' → 'Segoe UI' → 'Microsoft YaHei' → system-ui`。IBM Plex Sans 与 Segoe UI 都没有中文字形，**中文一定落在 `'Microsoft YaHei'` 上**（Windows 11 自带）。这带来两条推论：
  1. **中英混排的文字，字号与行高必须按中文来定**（中文的字面高度大于同字号的拉丁字，行高按拉丁的量级会给中文挤在一起）；
  2. **不要为了"更像中文界面"去引系统 UI 字体或另开一个字族** —— 那会让门禁层与九页的正文长得不一样，而这一屏正是要靠"看起来是同一个程序"来获得信任。
- `--mono` **只给机器字节**（命令、路径、主机名、版本号、校验相关的技术串）。中文**不进** `--mono`（既不美观，也会让"等宽=机器说的"这条既有信号失效）。

### 8.2 字号阶梯（只用既有的五档，不新增）

| 变量        | 值     | 门禁层与更新入口里的用处                                                           |
| ----------- | ------ | ---------------------------------------------------------------------------------- |
| `--t-state` | 22px   | **屏幕标题**：正在检查这台电脑上的运行环境 / 运行环境还没准备好 / 运行环境已经就绪 |
| `--t-lg`    | 15px   | 当前步骤的标题（第 N 步：…）、失败结论句                                           |
| `--t-md`    | 13.5px | 事实行的标题、选择项标题、进行中的状态行、按钮文字、面板标题                       |
| `--t-sm`    | 12.5px | 「为什么」、说明行、确认区事实值、横幅正文、结果行的说明句                         |
| `--t-xs`    | 11.5px | 左轨的状态词、提醒行、事实表的键、「将要执行」、元信息、pill、已下载 / 总量        |
| `--t-num`   | 22px   | **不用**（门禁层没有读数瓦片；数字的事实走 `--t-md` + `tabular-nums`）             |

**不需要新字号的理由**：这一屏的层级靠**位置与结构**表达（标题在屏上、卡在中间、队列在左轨、交代在卡外），不靠字号拉大。22px 的屏标题已经在既有焦点卡上验证过（那是这一屏上最大的一处字）。

### 8.3 行高、字距与断行

| 项         | 规格                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| 行高       | 22px / 15px 标题 1.2~~1.25；13.5px 与 12.5px 的正文 / 说明 1.7；11.5px 的补充行 1.6~~1.7；等宽输出 1.75               |
| 字距       | 沿用既有：15px 标题 `letter-spacing: -0.01em`、22px 标题 `-0.015em`；**中文不额外加字距**（不要用负字距去"收紧"中文） |
| 正文断行   | 正文、说明、结果句一律允许任意处断行（既有做法）；不出现横向滚动                                                      |
| 命令与路径 | 等宽 + 任意处断行 + **可选中** + **绝不省略号截断**（截断就等于不可复制）                                             |
| 元信息     | 只有"当行元信息"（例如状态栏那一类）允许省略号；门禁层里没有这类文字                                                  |
| 数字       | 版本号、百分比、已下载 / 总量、时间一律 `font-variant-numeric: tabular-nums`；版本号与百分比同时用 `--mono`           |

### 9.2 必须新增的颜色变量：**0 条**（附完整映射）

这一屏的每一处视觉需求都能落在既有变量上，因此**不新增任何颜色变量**，也就没有"新造一套配色"的问题。逐条映射如下（这张表同时也是一份"实现时该用哪个变量"的核对表）：

| 命令 / 路径 / 版本的文字           | `--code-ink`                                   |

| 滚动条                             | `--scroll-thumb` / `--scroll-thumb-hover`      |

**为什么三级不够、而四级表面正好**：门禁层要同时表达"底 / 框架 / 一张要读的卡 / 卡里的可选块 / 机器说话的井"五种关系，而框架层（`--rail`）在仓库里已经存在（左栏与状态栏），卡与可选块、卡与井分别靠 `--surface` / `--surface-2` / `--well` 三档拉开。因为**每一层都已有变量**，所以不需要新色。

**三条"不需要新颜色"的理由**（写给 freeze 评审）：

1. 状态四态各有现成色相（run / amber / rose / sky），两个"不是状态"的态本来就该是**没有色相的墨色**，不需要第五个色相；
2. 状态色在本规格里**只做小面积**（圆点、细线、文字），不做实心底 —— 于是不需要为每一种状态再配一个"底上的墨色"（`--accent` 之所以需要 `--accent-ink`，正是因为它有实底）；
3. 提示与横幅沿用既有软底（`--amber-soft`）+ 既有的 `--ink` / `--ink-dim` 文字，实测对比度 11.73 / 6.07（深色）与 14.42 / 6.02（浅色），不需要新的"软底上的字色"。

### 9.5 一处取值修订提案（浅色主题的四个状态色）

**问题**：§6.5 实测，浅色主题下 `--run`（3.15~~3.77）、`--sky`（3.42~~4.10）、`--rose`（3.92~~4.70）、`--amber`（4.19~~5.02）压在左轨与面板上都不足以承载 11.5px / 12.5px 的状态词。而这一屏的五个状态词**同时**出现在左轨（`--rail` 底）与卡片（`--surface` 底）两种底色上。

**提案**：只把浅色主题那四个状态色各加深一档，并同步它们的"软底"色相（软底只是 15% 透明度的晕，不承载文字）。**不新增变量、不改色相、不改深色主题**。

| 变量      | 浅色现值                 | 提案值                                                                                    | 压在 `--rail` 上（最差底色）   | 压在 `--surface` 上 |
| --------- | ------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------ | ------------------- |
| `--run`   | `#059669`                | `#047857`                                                                                 | 3.15 → **4.58**                | 3.77 → **5.48**     |
| `--sky`   | `#0284c7`                | `#0369a1`                                                                                 | 3.42 → **4.95**                | 4.10 → **5.93**     |
| `--rose`  | `#e11d48`                | `#be123c`                                                                                 | 3.92 → **5.25**                | 4.70 → **6.29**     |
| `--amber` | `#b45309`                | `#92400e`                                                                                 | 4.19 → **5.92**                | 5.02 → **7.09**     |
| 软底同步  | `rgba(5,150,105,.15)` 等 | `rgba(4,120,87,.15)`、`rgba(3,105,161,.15)`、`rgba(190,18,60,.15)`、`rgba(146,64,14,.15)` | 无文字，只为晕的颜色与主色一致 | —                   |

**影响面**：这四处同时是既有界面的状态色（环境自检页的灯与状态词、`--settings-status` 的"已保存"、输出区的完成 / 失败文字、耗时曲线等）。加深只会让它们在浅色底上更清楚，不会让任何一处变模糊；浅色块里已经有过同类先例（`--accent` 就是为对比度加深到 4.9:1 的，注释也留在原地）。

**若不接受**（这是一处**跨页面的取值修订**，属于集成收口的范围）：回退方案是 —— **状态词改用 `--ink` / `--ink-dim`，颜色只留在圆点与脊线上**（圆点不需要文字对比度）。代价是浅色主题下"用颜色区分三档"这条既有设计意图在文字上退让一半；两套主题仍然成立，对比度也全部达标。

## 10. 与既有界面的关系

### 10.1 与启动锁的交接

| 项           | 规格                                                                                                                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 是否同时出现 | **不**（交互 §2.1：互斥）。`blocked` 这一路根本不走自动启动，所以启动锁也不会出现                                                                                                                                                |
| 层号         | 门禁 `--z-gate` 低于启动锁；万一出现交接的一帧，也是启动锁盖住门禁，**不会**出现"半透明的门禁压住启动锁"的画面                                                                                                                   |
| 形状来源     | 两者是"同一族"的覆盖层（都盖住顶栏以下、都盖住左栏），但**长得不一样**：启动锁只需要说一句"等一下"（居中卡片 + 缺口环），门禁要让用户读完一份计划（左轨 + 文档列） —— 谁都不许抄对方的构图，抄了就会让用户分不清"是在等还是在做" |
| 交接时机     | 逃生 / 放行点下去之后才轮到启动锁（交互 §2.12）；门禁收起与启动锁出现之间不加过渡动画（两块都是整屏，叠动画只会闪）                                                                                                              |

### 10.2 顶栏与状态栏

- **状态栏**在门禁层显示期间被覆盖（门禁是不透明的 `--bg`），它的位置由**底条**占着 —— 所以门禁收起时，视线不需要重新定位底部（§5.2.1）。
- **顶栏不被覆盖**（交互 §2.1：窗口能拖、能关）。但顶栏里的**页面标题**此时不能继续显示"控制台"（用户看不到控制台，却被告知自己在控制台）。所以门禁层显示期间：
  - 页面标题显示 **运行环境准备**；
  - 右侧那些与页面相关的控件（地址、操作按钮）**收起**（不是禁用 —— 收起不占位，禁用会留下一个说不清用途的空槽）；
  - 门禁收起时立刻恢复原样（标题回到当前页、右侧控件回来）。
- 这是本规格提出的一处**很轻的界面增量**（需要改既有顶栏组件的取值来源），列在 §12 开口 3。

### 10.3 与"环境自检页 / 控制台横幅"的重复表达

交互 §10.3 已经把"谁说什么"分工定死（结论归自检页、怎么装归向导、更新归自检页、来源只有一处）。视觉上再补三条，保证用户看得出"这是同一件事的两个视角"：

| 关系                          | 视觉上的做法                                                                                    |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| 向导的事实行 ↔ 自检页的行     | **同一套解剖**（灯 + 结论词 + 结论原文 + 展开详情，§5.0 A），所以用户从向导进自检页会认出同一行 |
| 向导的确认区 ↔ 自检页的确认区 | **同一套件**（下沉井 + 左 3px 强调条 + 命令小砖 + 两列事实表），两处的"将要执行"长得完全一样    |
| 向导的输出区 ↔ 自检页的输出区 | 完全沿用既有输出区形态（含 38px 标题行与 220px 上限），不另画一套                               |
| 横幅 ↔ 向导                   | 横幅只**指路**（一个按钮），不重复讲步骤、不显示进度（否则用户会以为横幅自己会动）              |
| 更新入口 ↔ 安装入口           | 都在"行右侧的操作槽"里（同一位置），差别只是文案与出现条件（缺失给"安装"、可用给"更新"）        |

### 10.4 与聚焦蒙层、内嵌页的关系

- **不用聚焦蒙层**：既有的聚焦蒙层是"把注意力收拢到某一小块"（底栏更新提示 → 设置页的关于卡片）。门禁层要的是相反的语义（整屏接管），两者混用会让"必须处理"和"看一眼"变成同一种视觉。
- **内嵌页与终端页不进入**：门禁层显示期间，内嵌的 Harness 与终端都不该开始加载或滚动（交互 §2.10 的背景不可交互）。视觉上不需要额外处理（覆盖层不透明、整屏），但**不许**在门禁层上方再叠半透明的"背景预览"。

## 13. 明确不写的与禁止的做法

**沿用交互 §13 的措辞红线**：界面上不出现 `EnvCheckId`、`EnvFixPlan`、`EnvFixState`、`judgeEnvironment`、`probe`、`fixAction`、`verbatim`、`COMSPEC`、`NVM_SYMLINK`、`SHASUMS256`、`sha256:`、`PATH`。技术细节（路径、变量名、完整地址、退出码、校验值）只出现在**用户点开的**「展开看详情 / 命令原文 / 复制」区域里。视觉上还要多守一条：**详情区里的技术串也要看起来像"细节"**（等宽、下沉井、`--ink-dim`），不能因为它在详情里就当成正文排版。

**本文不写**（写了就是越权 / 会漂移）：

- 不写选择器实现、不写 Vue 模板、不写函数名与 IPC 名（交互规格已定：这些不属于规格）；
- 不写会随实现漂移的数字：自检项数、断言行数、脚本行数、版本号；
- 不写"推荐"标签、不给两条安装路径排名（那是主进程事实决定的默认值，不是视觉倾向）；
- 不写新的颜色、不写新的字体、不写新字号 —— §9.2 的"0 条新增颜色变量"是这份规格的硬结论。

**禁止的做法（视觉层面，review 时按这条查）**：

1. 把门禁层做成居中卡片 + 一个大按钮（§1.3 三条对照已经说明会失去什么）；
2. 给非当前元素做卡（后续步骤、提示块、提醒行都不许有阴影与卡片外观）；
3. 让整屏内容随状态变化而位移（检查中 / 挡住页 / 放行页的标题、卡片、底条必须在同一位置）；
4. 用颜色作为唯一的状态信号（形状与状态词永远是第一信号）；
5. 画假进度（算不出来就不画）、给"校验中"加流光、"不再等待"之后仍然显示进度条；
6. 失败时弹窗 / 跳页 / 整屏变红，或让左轨节点因为一次失败而变红；
7. 用强调色表示状态，或在一屏里放两处强调色实底。

## 14. 一句话留给实现者

**这一屏不是对话框，是这台应用把中段让给了向导**：它用应用自己的骨架（左轨 / 底条），把该读的一份计划左对齐地摊开，把"下一步只做什么"放在唯一一张有阴影的卡里，把失败与等待都留在原地，把颜色降回第二信号 —— 于是用户在机器还没准备好的时候，仍然能看懂、能读完、能随时走开，也随时能回来。
