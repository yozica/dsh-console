环境自检不再把主进程冻住，也不再去调"转发器"

真机上"双击没反应、过一会系统弹崩溃"的**真凶就是自检本身**：完整探测在主进程上跑 5 个同步
子进程（各 8 秒超时、串行），而它第一个就去敲了 `~/.vite-plus/bin/node` —— 那是个**转发器**，
在 GUI 应用的窄 PATH 下找不到系统 node，于是开始下载自己的运行时（100+MB）；8 秒到点被杀、
留下一个 `.tmp*`，下一个探测再起一个…… 界面在这几十秒里完全没响应。

- 探测改成**异步 + 并发**（超时就结束整棵子进程树、并释放管道）—— 不管对面是转发器还是任何
  慢东西，主进程都不会再因此卡住。
- **认得出转发器**：跟着符号链接看最终目标的名字还是不是 `node`（homebrew 那种指向真 node 的
  不算）。查找 Node 时真 node 优先、转发器垫底，而且**不去执行**它 —— 探测是只读的，不该替你
  在磁盘上装东西。
- **超时不再被说成"起不来"**：那是"它还在忙"，现在归到"测不出来"（黄灯）并给出人话，
  不再冒充"退出码 0 + 零输出"那条签名把你引去重装一个好好的 dsh。
- **「外部 Node」这一行报的是"真正会被用来跑 dsh 的那一份"**，并注明"dsh 就用这一份跑"；
  机器上还有一份被我们跳过的转发器时也会说明（"它的版本随启动环境而变，所以别拿它跟终端里的
  `node -v` 对账"）—— 这就是"自检显示 v24.21.0、终端显示 v22.17.1"那个困惑的答案。
