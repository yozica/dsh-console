# DSH Console

桌面控制台（Windows / macOS），用来管本机的 DeepSeek Harness（`dsh web`）服务：
**启停它、盯着它、看它吐出来的东西** —— 不用再开一个终端敲 `npx dsh`，也不用猜它到底起没起。

![界面截图](docs/screenshot.png)

|                       |                                                                                                           |
| --------------------- | --------------------------------------------------------------------------------------------------------- |
| **要什么**            | Windows 10/11 或 macOS 11+，加 Node.js（应用通过 PATH 找 `dsh`，见下）                                    |
| **怎么装（Windows）** | 下载 `DSH.Console.Setup.x.y.z.exe` 直接装；也可用免安装的 `DSH.Console.x.y.z.exe`                         |
| **怎么装（macOS）**   | 下载 `DSH.Console-x.y.z-arm64.dmg`（Apple 芯片）或 `DSH.Console-x.y.z-x64.dmg`（Intel），拖进「应用程序」 |
| **怎么跑**            | 打开即用：应用会自动拉起 dsh、打开内嵌的 DeepSeek Harness 界面并进入应用内全屏                            |

功能一览：

- **启停**：在真正的伪终端里拉起 `dsh web --no-open`，先尝试优雅退出，超时才强制结束整棵进程树
- **状态监听**：轮询健康检查 + 端口占用 + 进程存活，维护「停止 / 启动中 / 运行中 / 异常 / 端口冲突」状态
- **终端**：能看到 dsh 进程的全部输出（`dsh web` 不读键盘输入，界面里也如实这么写）
- **接管已有实例**：启动前先探测端口，发现别的 dsh 在跑就不重复拉起，转为「接管显示」
- **内嵌 DSH 界面**：用 dsh 打印的带令牌地址在窗口内打开，免开浏览器
- **本地 Shell**：窗口内另开一个 shell 排查问题，标签可重命名（不跨重启保留）
- **主题**：跟随系统 / 亮 / 深，终端配色跟着一起变
- **自动更新**：自动检查新版本，下载与安装都由你确认（macOS 因签名限制需手动下载）

## 它能做什么

左栏有八个页面，`Ctrl+1` ~ `Ctrl+8`（macOS 上是 `⌘1` ~ `⌘8`）依次切换。

### 控制台

一眼看出 dsh 起没起、起了多久、为什么没起。顶部状态条是指示灯 + 状态词 + 操作按钮 + 读数行
（PID、端口、延迟），下面占满剩余高度的是**事件日志**（本应用自己说的话：启动命令是
什么、健康检查结果、dsh 退出时它说了什么），右侧栏是进程操作（启动 / 停止 / 强制结束 /
重启）、延迟趋势与「将要执行的启动命令」。日志与状态都是给排错用的第一现场。

### dsh 终端

dsh 进程自己的输出视图：它打印的横幅、启动日志、报错都在这里，一屏不落。工具栏上有
**「发送 Ctrl+C」**（等价于让它优雅退出）、**「清空显示」**（只清当前画面）与
**「重新显示历史」**（把本应用缓存的历史输出重新画一遍）。

这里**打字不会有反应**，原因见「界面说明」——那是 `dsh web` 的行为，不是界面坏了。

### 本地 Shell

另开一个 shell 用来手工排查（Windows 是 pwsh / powershell / cmd，macOS/Linux 是 zsh / bash），
和 dsh 进程互不干扰：多个会话以标签（chip）形式排列，可切换、关闭、重命名。
**不跨重启保留**：应用一退出，会话和内容就没了，下次进来是干净的一页。

### DeepSeek Harness

把 DSH 的 Web 界面内嵌在窗口里，不用切浏览器。dsh 由本应用启动时会**自动捕获访问令牌**并载入；
页面还支持**应用内全屏**（藏掉左栏与状态栏，只留顶栏，`Esc` 退出）。
令牌拿不到时页面顶部会常驻提醒并给出可操作的出路（见「界面说明」）。

### DeepSeek 用量

内嵌 DeepSeek 开放平台的用量页，随时看 token 消耗。它本质是个浏览器视图，地址可以在
设置里改（默认是开放平台的用量页，不是官网主页）。登录态用独立分区保存，登录一次后免重复登录。

### 归档会话

DSH 的「归档」原本只是把会话隐藏起来、没有任何入口能找回来。这一页补上了：
按标题 / 首句 / 对话内容搜索归档列表，点开按「索引 + 转录稿」两栏读对话全文
（Markdown 正常渲染），也可以**恢复**到侧边栏或**删除**（删除会先确认，附件不动）。
读的是本机 DSH 数据目录，不经过网络。

### 插件

看清 dsh 的**插件是怎么装起来的**：profile 的 bundle 层栈（哪些是内置的、哪些是你装的、
谁覆盖了谁）、每个 bundle 的版本与来源、你自己的 patch 层，以及 `dsh web --dump-config`
组合出来的**生效配置**（按来源分层，可搜索、可筛选）。

**装 / 卸 / 升级也能在这一页做**：填包名（或 `./本地目录`、`.tgz`、`github:owner/repo#sha`）
点安装，输出边走边给你看；装完会提示「重启 dsh 后生效」并给一个「立即重启 dsh」的按钮。
树外插件在详情里各有「升级到最新」与「移除」。装插件等于让第三方代码跑在你的机器上 ——
确认框里会写明这一点，git 源建议固定 commit sha。

装 / 卸 / 升级要用 **pnpm**（dsh 通过它管理 profile 的依赖）：机器上没有 pnpm 时，页面会
先在安装框旁标出来，点下去也不会去改你的 profile，而是直接告诉你装一个再回来
（`npm i -g pnpm`，或 `corepack enable pnpm`）。**只读的部分不受影响** —— 层栈、条目、
生效配置都不经过 pnpm，没装也能看。

还会把"没报错的错"挑出来给你看：patch 里指向了不存在的条目、装进来的包没有声明
`dsh.bundle` 所以没形成层、列在层栈里却什么都没贡献的 bundle —— 这些都不会让命令失败，
但会让你的改动悄悄不生效。数据来自磁盘上的 profile、本机 dsh 命令，以及 dsh 自己的插件清单
（**dsh 没在跑也能看** —— 插件把 dsh 启动打挂时，这一页恰恰是唯一能用的入口）。

> 插件**自身的设置项**（比如 shell 执行器、subagent 模型）请到内嵌界面的
> **设置 → 插件** 里改 —— 那边管"运行中的插件能配什么"，这一页管"装了什么、怎么叠的"。

装 / 卸 / 升级默认用你电脑上的 npm 源。想单独指定一个（比如内网源里没有某个包，
或公司源不稳），在「设置 → 插件安装源」里填 registry：它只作为环境变量传给那一次
pnpm，**不改你的 npm 配置，也不影响别的项目**；留空就跟随系统。当前生效的源会显示在
插件页的安装框旁边。

### 设置

外观主题、用量页地址、服务端点、启动方式、监控与生命周期，全部集中在一页，见「配置项一览」。

## 下载与安装

在仓库的 Releases 页面下载对应平台的安装包。

### Windows

- `DSH.Console.Setup.x.y.z.exe`：NSIS 安装包，可选安装目录、建桌面快捷方式；
- `DSH.Console.x.y.z.exe`：免安装便携版，双击即跑。

（文件名是 electron-builder 按 `productName` 生成的：空格在文件名里会变成点，所以是 `DSH.Console.…` 而不是 `DSH Console …`。）

**覆盖升级**：拿到新版安装包直接装就是**原地覆盖** —— 不会新开目录、不会多出快捷方式，
升级时会自动关掉正在运行的旧版本。前提是打包用的 `appId` 与 `productName` 保持一致
（本项目的发行包一直是），并且版本号确实变了。升级后第一次启动，状态栏会说一句「已更新到 x.y.z」。

> 如果 Windows SmartScreen 提示「Windows 已保护你的电脑」，点**「更多信息 → 仍要运行」**即可：
> 这个包没有购买代码签名证书。

### macOS

- `DSH.Console-x.y.z-arm64.dmg`：Apple 芯片；
- `DSH.Console-x.y.z-x64.dmg`：Intel；
- 同名的 `.zip` 是免安装压缩包，解压即用。

macOS 包是 **ad-hoc 签名**（没有 Apple 开发者证书），首次打开会被 Gatekeeper 拦下，
提示「无法验证开发者」。三种放行方式任选：

| 方式             | 操作                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| 右键打开（推荐） | 在「访达」里**右键点应用 →「打开」**，再在弹窗里点「打开」；之后双击就正常了            |
| 系统设置里放行   | 先双击一次（会被拦），再到「系统设置 → 隐私与安全性」，在下方点**「仍要打开」**         |
| 去掉隔离属性     | 终端执行 `xattr -dr com.apple.quarantine "/Applications/DSH Console.app"`，之后直接双击 |

> 如果看到的是**「已损坏，无法打开」**而不是「无法验证开发者」，说明拿到的是 0.2.1 及更早的旧包
> （那时没有签名）；换用新版，或按上表最后一行去掉隔离属性。

覆盖升级：把新版 `.app` 拖进「应用程序」替换旧版即可，配置与日志都保留。

## 自动更新

两个平台都会**自动检查新版本**（启动几秒后一次，之后每 6 小时一次；设置里可关）。发现新版本后：

1. 设置页「关于」与底栏会出现提示，说明发现了哪个版本；
2. 点**「下载」**才开始下载（不会在后台偷偷下），下载时显示进度百分比；
3. 下载完点**「重启并安装」**才会退出并安装（也不会在退出时偷偷装）。

也就是说，**下载与安装这两个动作都要你点头** —— 升级会中断正在用的 DSH 服务，应用不替你决定。

> **macOS 能查、不能自动装。** 应用照样会检查并提示（底栏一句「发现新版本 x.y.z」、
> 设置页也会写明），但 macOS 包是 ad-hoc 签名（没有 Apple 开发者证书），系统的更新机制会拒绝
> 安装这类更新 —— 所以按钮是**「打开下载页」**：到
> [Releases 页面](https://github.com/yozica/dsh-console/releases) 下载新的 `.dmg` 覆盖安装即可
> （配置与日志都保留）。有了 Apple 开发者证书之后这半边才能真正自动化。

不喜欢自动检查的话，在「设置 → 监控与生命周期」里关掉**「自动检查更新」**即可；
关掉后仍然可以在设置页手动点「检查更新」。

## 使用前提

应用本身不实现 DSH 服务，它只是**拉起并管理本机已有的 dsh**。所以目标机器上需要：

1. **Node.js** —— `dsh` 依赖它运行；
2. **DeepSeek Harness（`dsh`）** —— 全局安装即可，例如 `npm i -g @deepseek-ai/dsh`。

找 `dsh` 的顺序是：**设置里手写的启动命令** → **`node` + 全局安装的
`@deepseek-ai/dsh/lib/bin.js`**（最可靠，进程 PID 就是 dsh 自己）→ 平台自带的 `dsh` 命令
（Windows 的 `dsh.cmd`，macOS/Linux 的 `dsh`）→ `npx -y @deepseek-ai/dsh`。

除了 PATH，应用还会主动去常见的全局安装位置找（nvm / fnm / nodenv 各版本目录、homebrew、
`~/.npm-global`、pnpm 全局目录）—— 因为从 Dock / 访达启动的 macOS 应用拿到的 PATH 很窄，
常常不含 homebrew 与 nvm。真找不到时，在「设置 → 启动方式 → dsh 命令」里手写一条完整命令
（例如 `/path/to/node /path/to/@deepseek-ai/dsh/lib/bin.js`）即可。

> nvm 用户注意：`npm i -g @deepseek-ai/dsh` 装在**当前 Node 版本目录**下，`nvm use` 换版本后
> dsh 就「不见了」。应用会扫各版本目录并实测挑一个能跑的，必要时也可以在设置里写死路径。

## 界面说明

### 启动行为（默认：起来就能直接用）

默认配置下，打开应用后会自己完成这一串动作，中间不需要点任何东西：

```
启动应用
  └─ dsh 没在跑？→ 用本应用拉起（已在跑则接管，不重复启动）
       └─ 健康检查通过 → 自动切到 DeepSeek Harness 页
            └─ 自动进入应用内全屏
```

三个开关都在「设置 → 监控与生命周期」，可以各自关掉：**启动应用时自动拉起 dsh**、
**就绪后自动切到 DeepSeek Harness 页**、**进入该页时自动开启应用内全屏**。

### 启动那几秒的锁屏

上面这串动作要花几秒，期间状态一直在变、点哪儿都不作数，所以启动期间会**锁住整个窗口**，
只显示一张卡片：转圈 +「正在启动 dsh 服务」+ 已等待秒数。就绪后自动解锁；
失败 / 异常 / 超过 90 秒 / 点「不等了，先进入界面」或按 `Esc`，都会立刻解锁
（锁只是免打扰，不是把人关在外面）。

### 应用内全屏与系统全屏是两件事

|        | 系统全屏（macOS 绿灯 / ⌃⌘F，Windows F11） | 应用内全屏（Harness 页的「全屏」按钮 / `Esc`） |
| ------ | ----------------------------------------- | ---------------------------------------------- |
| 谁在管 | 操作系统                                  | 应用自己                                       |
| 效果   | 窗口铺满屏幕，Dock / 菜单栏按系统规则隐藏 | 藏掉左栏、状态栏与页面工具条，只留 36px 顶栏   |
| 退出   | 再按一次系统快捷键                        | `Esc` 或顶栏的「退出全屏」                     |

全屏期间导航是隐藏的，所以任何切页动作（含 `Ctrl+1~7` / `⌘1~7`）都会先退出全屏。
标题栏用的是无边框样式，顶栏本身就是窗口标题栏，可以拖动窗口。

### dsh 终端：为什么打字没反应

`dsh web` 是个服务端进程，**不读 stdin**。所以「dsh 终端」页是**输出视图**，不是交互式终端 ——
打字没反应是 dsh 的行为，不是界面坏了。页面上方常驻一句说明，没有进程时还会直接给一个
「启动 dsh」按钮。唯一有意义的键盘输入是 **Ctrl+C**（工具栏按钮），它让 dsh 退出。

想输入命令请用「本地 Shell」页。

### DeepSeek Harness 页的访问令牌

`dsh web` 要求地址里带 `?token=…`，否则一律返回 `401 dsh web authentication required`。
这个令牌是**进程私有**的随机值（只在内存里），只在 dsh 启动时打印一次，**不落盘、也没有接口
能事后取回**。所以规则是「谁启动、谁截获」：

| 情形                         | DeepSeek Harness 页                                                                                                                                                    |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **dsh 由本应用启动**         | 令牌自动从输出里捕获，直接可用；dsh 重启后自动用新令牌重载                                                                                                             |
| dsh 已在外部运行（接管模式） | **拿不到令牌，内嵌界面不可用**。页面顶部有常驻提醒，首选操作是点**「重启为受管实例」**（结束外部实例后由本应用重新拉起），备选是把启动它的终端里那条完整地址粘进输入框 |
| 令牌失效（dsh 重启过）       | 载入后会提示鉴权失败；等新令牌被捕获即可                                                                                                                               |

> **想让内嵌界面可用，就让 dsh 由本应用启动**（首次启动，或对外部实例点「重启为受管实例」）。
> 注意「重启为受管实例」会**中断你正在使用的那个 Harness 会话**。

补充一点：如果你之前用浏览器打开过那个带令牌的地址，浏览器里的登录 cookie 会保留一段时间。
所以「在浏览器打开」在外部实例下通常仍可用（应用会先征求确认）。

### 深色 / 亮色主题

左下角有 **自动 / 亮 / 深** 三态开关，设置页里也有同一个「界面主题」下拉，两处随时同步，
改完立即生效并写入配置。

- **自动**：跟随系统的深色模式设置，系统切换时应用立刻跟着切，无需重启；
- 终端配色跟着主题一起变；
- 内嵌的 DSH Web 界面有自己的主题设置，**不受这里影响**（它是独立的网页）。

## 配置项一览

设置项保存在用户数据目录的 `settings.json`：

- Windows：`%APPDATA%\DSH Console\settings.json`
- macOS：`~/Library/Application Support/DSH Console/settings.json`

（「设置 → 打开配置目录」可直接跳转。目录名取自 `productName`「DSH Console」，**带空格**。
也可用环境变量 `DSH_CONSOLE_USER_DATA` 把配置目录改到别处。）

| 分组            | 设置项                             | 默认值                                | 说明                                                                               |
| --------------- | ---------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------- |
| 外观            | 界面主题 `themeMode`               | `system`（跟随系统）                  | 同左下角三态开关                                                                   |
| DeepSeek 用量页 | 页面地址 `deepseekUrl`             | `https://platform.deepseek.com/usage` | 改成 `https://www.deepseek.com` 就是官网主页；也可以填别的网址                     |
| 服务端点        | 监听地址 `host`                    | `127.0.0.1`（仅本机）                 | 可选 `0.0.0.0`（局域网可访问）                                                     |
| 服务端点        | 端口 `port`                        | `3080`                                | 填 `0` 让系统挑空闲端口，实际端口从 dsh 打印的地址里读回来                         |
| 启动方式        | dsh 命令 `dshCommand`              | 留空（自动探测）                      | 可写整条命令行，例如 `node 的绝对路径 + dsh 入口脚本`                              |
| 启动方式        | 附加参数 `extraArgs`               | 留空                                  | 拼在 `web --no-open` 之后，空格分隔、支持引号                                      |
| 启动方式        | 工作目录 `cwd`                     | 留空（用户主目录）                    | dsh 进程的工作目录                                                                 |
| 启动方式        | 本地 Shell `shell`                 | 留空（自动选择）                      | Windows：pwsh → powershell → cmd；macOS/Linux：`$SHELL` → zsh → bash → sh          |
| 插件安装源      | registry `pluginRegistry`          | 留空（跟随系统 npm 配置）             | 只作用于插件页的装 / 卸 / 升级，例 `https://registry.npmmirror.com`                |
| 监控与生命周期  | 状态轮询间隔 `pollIntervalMs`      | `1500` 毫秒                           | 越小状态越灵敏，开销也略高                                                         |
| 监控与生命周期  | 启动超时 `startTimeoutMs`          | `60000` 毫秒                          | 超过这个时间还没通过健康检查就判为异常                                             |
| 监控与生命周期  | 优雅停机等待 `stopGraceMs`         | `3000` 毫秒                           | 先请 dsh 自己退出，超时才强制结束进程树                                            |
| 监控与生命周期  | 自动拉起 dsh `autoStart`           | 开                                    | 已在跑就接管，不重复启动                                                           |
| 监控与生命周期  | 就绪后自动打开 `openUiOnStart`     | 开                                    | 自动切到 DeepSeek Harness 页                                                       |
| 监控与生命周期  | 进入自动全屏 `uiFullscreenOnStart` | 开                                    | 进该页时开应用内全屏，`Esc` 退出（外部实例拿不到令牌、页面还不可用时不会自动全屏） |
| 监控与生命周期  | 退出时停止 dsh `killOnExit`        | 开                                    | 只在关闭应用时停止**本应用启动**的 dsh；外部实例永远要手动确认才会被结束           |
| 监控与生命周期  | 自动检查更新 `autoCheckUpdates`    | 开                                    | 启动后检查一次，之后每 6 小时一次；关掉后仍可手动「检查更新」                      |

「保存」区还有 **保存设置**、**重新载入**、**打开配置目录** 三个按钮；
「关于」区显示应用版本与 Electron / Node / Chromium 版本，以及更新的当前状态与操作按钮。

## 常见问题

**点了「启动」起不来。** 先看「控制台」的事件日志，再打开「dsh 终端」页看 dsh 自己的完整输出。
三种典型原因：

1. **Node 版本跑不了 dsh**（最隐蔽）：dsh 的 CLI 在不兼容的 Node 上**不报错**，只安静退出
   （退出码 0、零输出），界面上只显示「已停止」。应用会**实测**后自动挑能跑的 Node；
   若你的环境比较特殊，就在「设置 → 启动方式 → dsh 命令」里写死
   `<能跑 dsh 的 node 绝对路径> <dsh 入口脚本绝对路径>`。判断哪个 node 能跑最快的办法是
   跑一次 `<node> <bin.js> --version`，**有输出**才行。
2. **端口被占**：该端口上已经有别的 dsh 在跑（最典型的是你正在用的那个 DeepSeek Harness，
   它默认也用 `127.0.0.1:3080`）。此时控制台会显示「运行中，外部实例」并禁用「启动」，
   还会显示占用该端口的 PID 与进程名。两条出路：改端口（设置 → 服务端点 → 端口，例如 3081），
   或到 Harness 页点 **「重启为受管实例」**（会中断当前 Harness 会话）。
3. **启动命令本身有问题**：例如退到了 `npx` 而 npm 缓存 / 网络异常。
   「dsh 终端」页始终是权威现场：dsh 的完整 stdout / stderr 都在那里。

**内嵌页面空白、只看得到顶部一小条。** 先确认 dsh 在运行。若这一页是「DeepSeek Harness」，
多半是拿不到令牌（外部实例）——按页面顶部提醒操作。若是「DeepSeek 用量」，可能是没登录，
点这一页的「在浏览器打开」登录一次即可（登录态随后会保留在应用内）。

**界面白屏 / 打不开。** 看日志文件，主进程所有日志与渲染层报错都会落盘：

- Windows：`%APPDATA%\DSH Console\logs\console.log`
- macOS：`~/Library/Application Support/DSH Console/logs/console.log`

看到「渲染层已连接」说明页面加载成功；只有 `[renderer:error] ...` 说明是脚本报错。
DeepSeek Harness 页里页面自己报的错（加载失败、请求被拦等）也会收进「控制台」页的事件日志。

**杀软 / 系统拦截。** 安装包没有商业代码签名，Windows SmartScreen 与部分杀软可能拦一下，
选「更多信息 → 仍要运行」或加入信任即可；macOS 的 Gatekeeper 放行方式见「下载与安装」。

**想彻底重来。** 关掉应用，删掉上面那个用户数据目录（配置与日志都在里面），再打开就是全新状态。
只想换配置目录的话，设置环境变量 `DSH_CONSOLE_USER_DATA` 指向别处即可。
